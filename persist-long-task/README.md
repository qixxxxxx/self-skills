# persist-long-task

`persist-long-task` 是一个用于长任务断点续做的 Codex Skill。它通过项目内的状态文件、原子步骤、检查点、失败尝试和恢复审计，让任务在上下文压缩、会话中断、长命令等待、Goal 自动续跑或 Agent 交接后，仍能从准确的位置继续。

它的核心原则是：**磁盘中的状态文件是执行真相源，聊天记录、Plan 和 Goal 只用于展示和协作。**

## 主要用途

适合以下任务：

- 预计需要较长时间或跨多个回合完成。
- 包含多个可以独立验收的步骤。
- 会修改多个文件或反复运行测试、模拟、构建命令。
- 需要尝试多种实现或排错路线。
- 可能遇到上下文压缩、工具中断或隔天继续。
- 用户要求持续执行、断点续做或配合 Plan/Goal 管理进度。
- 需要明确记录哪些文件已创建、修改、删除或临时生成。

对于一次就能完成的简单问答或小修改，通常不需要使用这个 Skill。

## 大致工作方式

整个执行循环可以概括为：

1. **初始化任务**：确定唯一任务根目录，把最终目标拆成能够独立验收的步骤。
2. **写入状态**：在任务目录下创建 `.codex/long-task/state.json` 和最新恢复快照 `journal.json`。
3. **开始当前步骤**：先记录当前步骤和唯一的下一动作，再执行实际工作。
4. **持续检查点**：完成一个工作单元、修改关键文件、准备运行长命令或可能中断时，立即保存摘要、文件变化、验证结果和下一动作。
5. **记录失败尝试**：实现或排错路线失败时保存动作、结果和原因，恢复后避免重复走同一条无效路线。
6. **证据完成步骤**：只有测试、产物或检查结果能够证明步骤完成时，才将该步骤标记完成。
7. **最终审计**：全部步骤结束后，核对状态、实际文件和最终验证结果，再完成整个任务。

状态由 `scripts/task_state.py` 管理，不应直接手工编辑 JSON。

## 状态文件记录什么

`state.json` 会保存：

- 最终目标、工作目录、范围和约束。
- 任务步骤及每步验收条件。
- 当前步骤和唯一 `next_action`。
- 最近的检查点和有界历史记录。
- 当前步骤最近的失败或成功尝试。
- 已修改、创建、删除、临时或确认未变的文件。
- 验证证据、关键决定和阻塞原因。
- 用户调整目标或范围后的修订记录。

`journal.json` 是绑定当前 `state.json` 的最新恢复快照。当状态文件缺失、损坏或写入中断时，可以通过恢复或修复命令重新建立一致状态。

## 恢复时会做什么

每次新回合、上下文压缩、Agent 交接或长时间等待后，Skill 会先执行恢复门禁：

1. 读取状态和最新快照。
2. 检查 Git 状态、实际文件、关键产物和最近验证结果。
3. 比较现场与记录是否一致。
4. 已有证据证明完成的内容不再重做。
5. 有部分产物时从缺失部分继续。
6. 状态冲突时先记录和排查，不直接覆盖文件。
7. 确认一致后，只执行状态中记录的唯一下一动作。

这种方式可以防止模型仅凭聊天摘要重新规划任务，导致遗漏、重复修改或重复失败。

## 调用示例

可以直接向 Codex 提出：

```text
使用 $persist-long-task 执行这个跨多轮重构任务，为它建立可恢复状态并持续记录检查点。
```

或者：

```text
这个任务会运行很久，并且可能发生上下文压缩。请使用 $persist-long-task，把调查、实现和最终验证拆成独立步骤后继续执行。
```

使用时最好明确：

- 可验收的最终目标。
- 本次包含和不包含的范围。
- 不得违反的约束。
- 任务根目录或仓库路径。
- 重要的最终验证方式。

## 常用状态命令

脚本使用当前环境规定的 Python，并始终传入绝对的 `state.json` 路径：

```bash
/Users/lq/slot_math_env/bin/python \
  /Users/lq/.codex/skills/self-skills/persist-long-task/scripts/task_state.py \
  --state /绝对任务目录/.codex/long-task/state.json <命令>
```

常见命令包括：

- `init`：初始化任务和步骤。
- `resume`：恢复状态并显示唯一下一动作。
- `begin`：开始一个步骤。
- `checkpoint`：保存当前成果、证据和下一动作。
- `attempt`：记录一次实现或排错尝试。
- `complete`：用证据完成一个步骤。
- `revise`：记录目标、范围或约束调整。
- `block` / `unblock`：记录和解除阻塞。
- `audit`：审计状态和恢复快照的一致性。
- `finish`：在全部完成条件满足后结束任务。

这些命令通常由 Codex 自动调用，使用者不需要手动维护状态。

## 使用特点与注意事项

- 已有未完成状态不会被覆盖；如果目标不同，会先询问用户。
- 已有有效证据的步骤不会重复执行。
- `next_action` 必须具体且唯一，不能只写“继续处理”。
- 多 Agent 协作时只有主 Agent 写入状态，其他 Agent 只提供结果和证据。
- `.codex/long-task/` 默认属于本地运行元数据，未经用户同意不会提交到仓库，也不会擅自修改 `.gitignore`。
- 状态通过最终审计前，不会仅凭“代码写完了”宣称任务完成。

## 目录说明

- `SKILL.md`：长任务持久化的核心协议。
- `references/state-schema.md`：状态结构、字段和恢复规则。
- `references/plan-goal-workflow.md`：与 Plan、Goal 配合时的同步方式。
- `scripts/task_state.py`：状态初始化、检查点、恢复、审计和完成工具。
- `agents/openai.yaml`：Codex 界面展示和默认调用提示。

README 面向使用者提供概览；实际执行时以 `SKILL.md` 和 `references/` 中的规则为准。
