# 阶段5-交付清单

> 由`seal_delivery.py`确定性生成。以下每章的展示方式、字段顺序、空值规则和实例均为强制契约。

## 一、交付结论与上线资格

- 展示方式：三列表格，一项交付结论一行。
- 必需字段：项目、结果、含义/通过标准
- 空值规则：数值不通过或无法判定时，上线资格必须为“不可上线”，但可形成审计交付。
- 展示实例：
```markdown
| 项目 | 结果 | 含义/通过标准 |
|---|---|---|
| 上线资格 | 可进入人工上线评审 | 交付完整不等于自动发布 |
```

## 二、最终结论来源

- 展示方式：四列表格，一项权威结论源一行。
- 必需字段：对象、路径、SHA-256、职责
- 空值规则：阶段4报告或交付JSON缺hash时交付阻塞。
- 展示实例：
```markdown
| 对象 | 路径 | SHA-256 | 职责 |
|---|---|---|---|
| 阶段4中文报告 | 04-alignment/阶段4-数值对齐报告.md | abc… | 最终人类结论 |
```

## 三、必需文件与职责清单

- 展示方式：六列表格，一份交付文件一行。
- 必需字段：路径、阶段、职责、必需、有效、SHA-256
- 空值规则：必需文件不存在或hash失效时`有效=false`且交付状态阻塞。
- 展示实例：
```markdown
| 路径 | 阶段 | 职责 | 必需 | 有效 | SHA-256 |
|---|---|---|---|---|---|
| 03-scoring/stage3_gate.json | 03-scoring | 阶段转换门禁 | true | true | abc… |
```

## 四、逐项交付检查与证据

- 展示方式：五列表格，一项检查一行。
- 必需字段：检查ID、检查名称、状态、通过标准、证据/错误
- 空值规则：检查证据为空时不得标为通过；错误必须原样保留。
- 展示实例：
```markdown
| 检查ID | 检查名称 | 状态 | 通过标准 | 证据/错误 |
|---|---|---|---|---|
| report-contract | 五阶段报告契约 | 通过 | 标题、字段和重渲染一致 | validate_artifacts.json |
```

## 五、不可变版本与Hash封存

- 展示方式：三列表格，一项封存属性一行。
- 必需字段：项目、值、规则
- 空值规则：版本号、生成时间或Hash算法缺失时不得更新根目录最新清单。
- 展示实例：
```markdown
| 项目 | 值 | 规则 |
|---|---|---|
| 版本目录 | versions/dv0001/ | 创建后不得覆盖 |
```

## 六、限制、风险与上线建议

- 展示方式：三列表格，一项授权边界或风险一行。
- 必需字段：事项、结论、要求
- 空值规则：未明确授权的配置同步、热更新、发布和Git提交一律写“未授权”。
- 展示实例：
```markdown
| 事项 | 结论 | 要求 |
|---|---|---|
| 配置同步 | 未授权 | 不得自动覆盖active cache或同步sl-config |
| 交付后Server Flow审计 | 封存后单次执行 | 结果只警告，不影响FORMAL、封包或本清单状态 |
```

## 七、回退与复算方法

- 展示方式：三列表格加bash代码块；按变更来源列回退阶段。
- 必需字段：场景、动作、返回阶段、validate_artifacts.py、seal_delivery.py
- 空值规则：回退阶段必须是1至5之一；命令必须使用实际Python环境和路径。
- 展示实例：
```markdown
| 场景 | 动作 | 返回阶段 |
|---|---|---|
| 指标合同变化 | 重新密封合同并评分 | 阶段2 |

<python_bin> <skill_root>/scripts/validate_artifacts.py --artifacts <artifacts>
```

## 八、历史版本

- 展示方式：四列表格，一版本一行。
- 必需字段：当前版本、目录、状态、说明
- 空值规则：没有更早版本时仍展示当前版本，并声明更早版本不存在或保持只读。
- 展示实例：
```markdown
| 当前版本 | 目录 | 状态 | 说明 |
|---|---|---|---|
| dv0001 | versions/dv0001/ | 通过 | 更早版本保持只读 |
```
