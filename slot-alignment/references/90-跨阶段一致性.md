# 跨阶段一致性

每个阶段输出都绑定`task_id`、`game_code`、`mode`、`rtp_group`、目标 RTP、Schema 版本、生成器版本和输入 hash。

最小失效规则：

| 变化 | 最小退回 |
|---|---|
| 规则、协议、server、脚本、Runtime、作用域、参数权限 | 阶段 1 |
| 玩法画像、语义库、指标库、指标汇总指纹、Owner、语义角色、派生关系、控制关系、豁免 | 阶段 2；结构不可达自动豁免在阶段4生成后退回阶段3重算派生政策与评分 |
| 目标、组件RTP贡献占比或映射政策、基础容差、容差系数、容差政策、Jackpot物质性政策、有序轴语义/变换/尺度政策、评分组政策、样本能力政策或计划、评价合同、score_budget_key、作用域聚合、权重、评分脚本 | 阶段 2；评分变化继续退回阶段 3 |
| 候选参数、样本计划、种子、预算、可达性上限状态、FORMAL 计划 | 阶段 4 |
| 仅报告或清单生成器且机器事实未变 | 重生成并复验阶段 4/5 |

检查上一阶段输出可直接成为下一阶段输入；禁止同名不同义、单位变化、范围变化、重复Primary Owner、派生项计分、循环依赖、作用域实例自然增权和 Markdown 与 JSON 状态不一致。`references/指标目录/指标汇总.md`必须与当前玩法/指标JSON逐字节确定性一致，不能成为手工维护的第二事实源。

阶段转换是强制机器门禁，不是展示步骤。阶段3到阶段4必须同时满足：`artifacts/03-scoring/scorecard.json`存在、当前`report_dir/阶段3-评分报告.md`为机器结果的确定性输出、基线测量源及合同hash有效、评分可判定、`stage3_gate.json`通过。缺少任一项时，即使`work/`中已有基线或候选scorecard，也不得创建新候选或继续CALIBRATION。

新任务还必须先通过`semantic_contract_validation.py`：当前玩法/指标索引hash、`input_manifest`、`game_profile`和`parameter_authority`hash有效；四份任务身份与作用域一致；玩法必需属性、目录命中指标、合同不可变语义、包映射、覆盖率及互斥Owner均由机器重算。空画像、空合同、漏Core、漏专项指标、伪造100%覆盖率或只自证目标值一律阻塞。历史复算必须显式使用`--historical-replay`，且v2.5～v2.9及v3.2原机器合同的版本、身份、作用域、目录绑定、非空玩法/指标和覆盖率完整；缺失、未知或未来版本一律阻塞。一旦重新进入阶段2或上游hash变化，必须迁移到当前合同。

阶段1至5中文报告统一位于当前`交付物/报告文档/rv####/`，并绑定统一报告展示契约：模板逐章规定展示方式、必需字段及顺序、空值规则和Markdown实例；模板和实报的章节顺序必须一致，各章节必须有内容，字段不得缺失，表头不得改名或调序，实报不得残留占位符，并且必须与当前机器JSON确定性重渲染结果一致。阶段3转换门禁复核阶段1至3；阶段4预交付校验复核阶段1至4；最终交付校验复核全部五阶段和FORMAL Runtime四件套。

v3.3起，阶段1的用户直接认证证据和已认证Python脚本hash随`input_manifest.json`参与全部上游hash传播。脚本hash变化时，阶段1认证及全部下游结果失效；交付后不再追加服务端验证。

v4.0起，`preflight_input_confirmation`、`preflight_decision_gate`和连续执行政策参与状态传播。正式开工前，最终有效样本数、Python脚本文件名/绝对路径/Hash必须由用户确认，用户要求的全量重算必须覆盖全部已发现源，且指标库缺口必须为0；`input_manifest.json`变化会通过上游Hash使后续合同和报告失效。自动豁免后必须重算有序距离活动实例、评分组权重、样本能力政策、阶段3 scorecard/报告和`stage3_gate.json`。FORMAL结果只能绑定重算后的合同与政策摘要。

阶段3到阶段4门禁属于流程完整性修复，不是评价标准变更。已有任务只要尚未完成并需要重新进入阶段4，也必须先补齐真实阶段3产物并通过门禁；不得根据后续候选结果倒推或改写阶段3基线。已完成历史交付不回溯重写。

已有任务不得因默认容差、Jackpot物质性、有序距离、评分组或样本能力政策升级而自动失效；只有任务主动采用新政策时才创建新合同版本并按上表退回。新任务固定使用`game_profile 1.2`、最终`metric_contract 1.4`和`slot-alignment.reports.v3.3`；1.3只允许作为政策链展开中间合同，历史复算继续保留原版本，不得把新合同临时降级成旧Schema绕过校验。

组件 RTP 占比映射和预算可达性上限作为新任务默认政策；已有已密封任务不自动回溯，只有主动采用时才创建新合同版本并按上表退回。
