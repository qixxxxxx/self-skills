# 跨阶段一致性

每个阶段输出都绑定`task_id`、`game_code`、`mode`、`rtp_group`、目标 RTP、Schema 版本、生成器版本和输入 hash。

最小失效规则：

| 变化 | 最小退回 |
|---|---|
| 规则、协议、server、脚本、Runtime、作用域、参数权限 | 阶段 1 |
| 玩法画像、语义库、指标库、Owner、控制关系、豁免 | 阶段 2 |
| 目标、评价合同、权重、评分脚本 | 阶段 3 |
| 候选参数、样本计划、种子、预算、FORMAL 计划 | 阶段 4 |
| 仅报告或清单生成器且机器事实未变 | 重生成并复验阶段 4/5 |

检查上一阶段输出可直接成为下一阶段输入；禁止同名不同义、单位变化、范围变化、重复 Owner、循环依赖和 Markdown 与 JSON 状态不一致。
