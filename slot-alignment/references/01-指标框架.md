# v5指标框架

## 顶层唯一Owner

四个顶层分类互斥且完备：

1. 数值指标N：跨完整付费入口或组件的全局数值红线。
2. 中奖结算J：完整结算链中的实际派奖结果。
3. 玩法过程P：跨结算步骤的Feature周期和机制结果状态。
4. 盘面呈现B：稳定可见盘面的视觉符号构成、关键符号数量与空间结构。

归属冲突时按“结果属于J、过程属于P、静态画面属于B、全局红线属于N”处理。Cascade连续消除属于J3，不属于P。

## N：数值指标

N类固定六张硬门禁卡，逻辑保持独立，不参与J/P/B距离评价。

| ID | 指标 | 定义 |
|---|---|---|
| N1 | 总RTP | `sum(完整付费入口总派奖)/sum(实际经济投注)`；目标为用户确认的唯一数值 |
| N2 | 完整付费入口中奖率 | `P(return > 0)` |
| N3 | Feature自然触发率 | 每个Feature分别评价`P(自然进入Feature)` |
| N4 | 完整付费入口回报≥1x概率 | `P(return >= actual_entry_cost)`；Feature Buy按实际购买成本 |
| N5 | Sigma | 总体及画像要求的适用作用域作为卡内子项 |
| N6 | 组件RTP贡献 | Base、各Feature和其他组件作为卡内子项 |

N1目标必须由用户直接提供或明确确认，机器值必须位于`(0,1]`，禁止使用目标区间。资料只能提供候选值和核验证据；没有用户确认记录时不得生成指标合同。N6逐组件目标使用原版组件贡献占比乘以该用户确认总RTP得到。

N4边界包含1x。原付费入口倍率分布、200x以上长尾、最大中奖和封顶只作审计。

### N类C级玩家预算

| 卡 | C级最大允许差距 |
|---|---|
| N1 | 绝对RTP差`0.003`，即±0.3个百分点 |
| N2 | `min(max(目标 × 6%, 0.008), 0.02)` |
| N3 | 普通Feature为目标的`12%`；目标`<0.0005`时为`20%` |
| N4 | `min(max(目标 × 8%, 0.005), 0.015)` |
| N5 | 总体`8%`；Base及其他非Feature作用域`8%`；Free Spin、Respin、Hold & Spin等各Feature作用域`12%` |
| N6 | `min(max(目标 × 8%, 0.003), 0.015)` |

N5通过玩法画像的`features[].feature_id`识别Feature，不写死`free-spins`名称。原版自对照波动只用来判断是否需要增加样本，不得扩大N类C级预算。

## J：中奖结算

### J1 中奖内容构成

逐组件冻结2～5个玩家看得懂、完整覆盖该组件派奖元素的中奖内容组，评价：

```text
P(中奖组参与 | 当前组件发生正派奖步骤)
```

每个派奖元素只属于一组；同一有奖结算可同时出现多组，所以参与率不要求合计为100%。同一组在一步里出现多份也只计“出现过一次”，中了几份由J2负责。优先使用主题/最高价值、其他高价值、低价值和确实直接派奖的特殊组。Wild只做替代时不单独分组，只触发玩法但不直接派奖的符号不进入J1。只有一个派奖元素的组件不生成J1。

### J2 单次结算体验

保留三个玩家维度：

- 主要中奖结构规模：每个`组件 × 结算模型`最多保留一个玩家最容易看懂的主轴。Payline为连中轴数，Ways为实际Ways数，Count Pay为派奖符号数，Cluster为连片格数，全屏消除为消除格数。像3/4/5连这类少量自然档位，比较各档占比和整体移动量；Ways、Cluster等大范围数值比较平均值、P50“常见规模”和P90“较大规模”。
- 同时中奖数量：逐组件统计一个有奖结算中亮出的独立中奖份数，默认档位为`1、2、3、4+`；稀少高值尾部可在候选出现前合并成`3+`等最终档位。
- 单次结算奖励：每个正奖励结算步骤分别统计`当前步所有可见奖励合计 / 玩家界面展示投注基准`，比较平均值、P50“常见奖励”和P90“较高奖励”。连续结算每一步分别记录，不合并为整链奖励。

逐元素结构、逐线路结构及同一结算模型的第二结构轴不生成指标。Base、各Feature和其他玩家可区分组件不得合并；Feature Buy购买成本不作为J类奖励分母。

### J3 连续结算

深度定义为“同一可连续结算入口内，实际发生的正奖励结算步骤数”。所有作用域统一使用：

```text
0、1、2、3、4、5、6+
```

0表示没有任何正奖励步骤，1表示只结算一步后结束，6+合并六步及以上长尾。每个合格入口必须且只能进入一档。逐深度reels、Ways、结构规模、继续概率和各层RTP贡献均不生成指标。整链奖励彻底删除，不通过、不评分、不保留辅助观察。

## P：玩法过程

### P1 玩法入场与长度

P1回答两个玩家问题：进入玩法时拿到哪档起始资源，一整轮实际会经历多少个主要动作。

#### 入场奖励档位

只对玩家可见且实际可变的入场奖励生成指标，例如Free Spin初始`8/12/20次`、Hold & Spin初始重转档位、Pick玩法初始选择次数。正式Facet为：

- 每个冻结入场档位的条件占比；
- 整套入场档位的整体移动量。

原版和候选都按`P(入场档位 | 当前Feature入口)`统计。平均初始次数不生成正式指标，因为相同平均值可能掩盖中间档消失和高档翻倍。固定给10次Free Spin、固定3次Respin等属于玩法规则，不生成概率指标并要求规则完全一致。

#### 完整玩法长度

每次完整Feature得到一个整数长度：从触发入口旋转结算完毕、Feature正式开始，到没有剩余动作或待执行阶段为止，统计玩家实际经历的主要动作数。只使用完整记录到结束的Feature周期。

| 玩法 | 一次主要动作 |
|---|---|
| Free Spin | 实际执行一次免费旋转，包括重触发后真正玩掉的旋转 |
| Hold & Spin / Respin | 执行一轮玩家可见的完整重转结果 |
| Pick / Award | 完成一次实际选择或抽取 |
| 阶段玩法 | 完成一个独立可玩的阶段 |
| 混合玩法 | 出现一次新的玩家可见玩法结果步骤 |

触发玩法的普通旋转、Cascade层数、同一步中奖数、动画、收集元素数量、升级提示、Reset/Add/Replace事件本身都不增加长度。新增次数只在实际执行时计数。Free Spin内触发的Hold & Spin等嵌套Feature单独统计自身动作，子Feature动作不重复加入父Feature长度。

可变长度比较平均、P50和P90；固定长度属于规则，不生成分布指标。重触发次数、Reset次数、续命次数和延长事件不独立评价，它们的玩家影响已由最终实际长度承担。

### P2 特色机制结果

P2统一回答：每次机制有机会运行时，玩家最终看到了哪一种结果。每个机制必须冻结机会单位、机制家族、结果评价模式、是否必然出结果，以及2～6个互斥完备的玩家可见状态。

主流机制家族固定为：

1. `multiplier_modifier`：Wild倍数、随机倍率、结算修正；
2. `collection_upgrade`：收集、进度、升级、解锁；
3. `transform_replace`：Mystery、变换、替换、符号升级；
4. `expand_persist`：扩展、黏住、Walking、持续存在；
5. `respin_special_result`：Hold & Spin或Respin中的Collector、升级、填满等特殊结果；
6. `random_modifier_selection`：Feature入口或过程中抽取Modifier/增强包；
7. `pick_wheel_path`：Pick、转盘、路径和阶段选择；
8. `other`：无法归入上述家族但玩家能清楚区分的机制。

机会单位按机制真实运行节奏冻结为Feature Spin、正奖励结算步骤、Feature入口、完整Feature、Pick、Respin步骤、玩家可见动作或other。不能统一按付费入口统计。

正式Facet为：

- 每个冻结玩家结果状态的条件占比；
- 整套结果状态的整体移动量。

非必然机制必须包含“没发生”或“发生但没生效”状态；保证每次必然给出结果的机制可以不设无效状态。一次机会只能进入一个状态。多个独立效果同时出现时，按玩家能区分的机制拆开；不得展开大量组合状态。

Buffalo Wild倍数可表达为：没出现、出现但没参与中奖、实际生效2x、实际生效3x、实际生效4x+。Wild数量和位置属于B；最终赢分属于J2；P2只承担倍数机制给出的玩家结果。收集升阶默认按完整Feature最终达到的等级统计，除非升级时机本身是核心体验，才增加候选前冻结的早/中/晚/未升级结果机制。

固定、条件必然且只有一个可达结果的机制不生成P2分布实例，继续按玩法规则要求完全一致。

## B：盘面呈现

只统计玩家实际看到的稳定盘面，不统计动画临时帧。B类不追求逐格复刻，也不按卷轴、行或区域评价普通符号构成。

### 正式盘面作用域

每个组件最多冻结两类正式盘面：

- `initial`：一次主要动作的初始落盘。
- `cascade_visible`：发生连续结算后玩家看到的补位稳定盘，包括最后一次无新中奖的补位终盘；未发生连续结算时，不把initial再次记录为terminal。

Base与Feature分别实例化；`initial`与`cascade_visible`不得合并平均。原始terminal、具体cascade层级和其他阶段盘面只保留在A5审计。

### B1 元素组成与聚集

#### B1-1 全盘普通符号构成与组内平衡

- 每个正式盘面冻结2～4个互斥普通符号组，优先使用主题最高价值组、其他高价值组和低价值组。
- 组间比较各组占全部有效格的长期比例，并检查整套组占比的半L1移动量。
- 包含两个或以上符号的组继续比较各成员在组内的相对占比，并检查组内总变差。
- 所有多符号组共同组成一个组内平衡维度，成员或组更多不会增加B1-1权重。
- 不检查各卷轴、各行、各区域的普通符号组比例；明确的固定轴或禁用轴属于规则一致性，不扩展B1-1。

#### B1-2 关键元素数量与未触发盘面

- Wild、Scatter/Bonus、Collector等关键元素按候选前冻结的自然数量档位比较各档占比与整体总变差。
- 触发型元素由N3/P类负责成功触发率；B1-2只统计未触发盘面的`0～触发阈值-1`，避免重复处罚。
- 非触发型关键元素优先使用`0、1、2、3+`等玩家能理解的少量档位。

#### B1-3 主要堆叠或聚集形态

每个正式盘面最多冻结一种主要聚集口径：

| 盘面类型 | 主要口径 |
|---|---|
| 普通卷轴、Stacked Symbols | 同符号纵向连续长度 |
| Cluster | 最大同符号连片格数 |
| 全屏消除 | 最大同符号集中规模 |
| 其他 | 一个候选前冻结、玩家能理解的等价单位 |

普通卷轴优先使用`未出现、单个、连续2格、连续3格、连续4格+`。J2负责实际派奖结构，B1-3负责所有稳定盘面的聚集；若两者高度重复，B1-3只统计未中奖盘面，仍完全重复则不生成。独立“单盘重复程度”不再生成。

每个正式盘面的普通符号组与关键元素必须互斥且完整覆盖可见符号域。

### B2 盘面形态

B2只保留玩家能直接看出的整体盘面轮廓：

- 固定盘面只要求规则一致，不生成分布实例。
- 可变卷轴高度逐卷轴比较各高度档位占比与整体总变差。
- 全盘有效格数比较mean、P50和P90。
- 盘面参差程度定义为`最高卷轴高度-最低卷轴高度`，比较mean和P90。

关键元素精确位置、逐格热力图和旧B2-2彻底删除，不生成正式指标、分数或辅助观察。

### Buffalo示例

Buffalo普通组可冻结为`h1`、`h2-h5`、`l1-l5`。如果`h2-h5`整组总量正确，但内部从各25%变成`55%/15%/15%/15%`，组间构成通过而组内平衡失败。B2只检查六根卷轴的高度档位、全盘有效格数和高低参差，不再检查WILD/BONUS精确坐标。

## 卡内子项规则

- 中奖组、组件、结算模型、Feature、机制、符号和盘面作用域只按本框架规定扩展卡内子项，不因子项数量多就让该卡在分类分中占更大比重。
- 每个命中子项都必须先通过；任一子项失败，卡直接失败。N卡通过后对子项分取平均。J/P/B卡通过后按“实例组 → 维度 → 卡”分层评分，分布型实例按“整体50% + 各档平均50%”计算，避免档位、符号、卷轴或玩法更多的游戏天然获得更大权重。
- 玩法画像证明机制不存在时才可不实例化；实例化后不得豁免。
- 固定、条件必然、单一可达或由其他正式指标确定性覆盖的J细项直接不生成；其他分类只有政策明确要求时才保留独立规则审计。
