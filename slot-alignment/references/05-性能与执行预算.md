## 固定样本计划

CALIBRATION和FORMAL统一读取`sample_execution_plan.json`。默认RNG协议为`chunk_seeded`；`crn_v1`只能用于隔离诊断。原版目标低样本只会改变实例的活动/观察角色，不会降低这里的候选、独立复核或FORMAL样本要求。

### CALIBRATION

| 阶段 | 累计完整付费入口 | 范围 |
|---|---:|---|
| 初筛 | `100000` | 全部候选 |
| 复筛 | `500000` | 晋级候选 |
| 决赛 | `2000000` | 决赛候选 |
| 独立复核 | 另跑`2000000` | 排名前2名，使用独立seed |

Worker数、micro-batch大小和执行次数都不能改变总样本、分片seed或最终结果。

### FORMAL

固定档位为`10000000`、`20000000`、`50000000`。对每个活动条件实例冻结“一个完整付费入口是否进入该实例整体有效分母”的暴露概率：

```text
所需入口数 = ceil(2000 / 条件暴露概率)
```

选择覆盖全部活动条件实例的最小档位。观察项不参与FORMAL样本档位计算，也不要求候选测量；达到最低原版证据线的`active_low_sample`仍是活动实例，必须正常参与。不能使用某个稀有状态或桶的概率代替整体分母概率。

例子：某P2机制平均每5000个付费入口得到一次完整Feature机会，暴露概率为`1/5000`，预计需要1000万入口得到2000次机会。不能再因为“4x+”状态只占1%而把要求提高到2亿入口。

若5000万入口仍不足，完成该档并把受影响实例标为`样本不足/U`。禁止运行中静默改档或增加自定义样本门槛。

## 两层观测

### 完整等价观测层

只在有界确定性小样本上保存完整事件，验证：

- RNG调用位置、次数、顺序和最终状态；
- 逐入口投注、总派奖和组件派奖；
- Feature、状态机、触发、重触发和结束；
- 盘面、中奖步骤、连续结算和守恒；
- 全部正式N/J/P/B原始测量。

自然随机难以覆盖的路径使用固定输入或确定性验证案例。不能为了覆盖而重抽结果。

### 流式正式观测层

CALIBRATION和FORMAL使用已经通过等价验证的流式观测器：

1. 生成一个入口或一个批次；
2. 在内存中完成结算和正式观测；
3. 立即更新有界累计器；
4. 释放入口状态；
5. 分片结束后写聚合和checkpoint。

不得把逐入口JSON、逐RNG记录或完整状态哈希带入大样本热路径。允许保存有界审计样本，但抽样规则和上限必须在计划中冻结，且不能改变RNG流。

## 流式累计器

正式指标在运行前编译成固定整数索引和有界数组：

| 指标类型 | 推荐累计方式 |
|---|---|
| 概率/比例 | 成功次数、有效分母 |
| RTP | 缩放整数投注和派奖总和 |
| Sigma | 固定作用域的`count/sum/sum_square`或稳定在线算法 |
| 固定档位分布 | 预分配整型计数数组 |
| mean | `count/sum` |
| P50/P90 | 冻结的有界自然支持计数；超界进入预定义overflow桶 |

累计器基数只能由冻结合同决定，不能随样本数、精确赢分或动态字符串增长。若自然支持确实无界，在候选前冻结业务可接受的有界桶和overflow状态，并证明不会改变正式统计语义。

单Worker内存复杂度必须相对总入口数为`O(1)`；这里表示内存只随冻结指标和Runtime规模变化，不随累计局数线性增长。

## 热路径约束

总入口数达到10万及以上时，禁止：

- 写全量逐入口JSON/NDJSON后再读回聚合；
- 为每个随机点新建RNG对象；
- 为每局或每次RNG调用计算独立hash；
- 在热路径做Decimal字符串转换；
- 逐入口更新TDigest；
- 按精确赢分维护无界Counter/dict；
- 逐入口拼接字符串key；
- 逐入口创建业务dict、dataclass、list或完整结果对象；
- 为观测重复执行完整结算；
- 在每个分片重复解析Runtime、编译JIT或构建候选采样表。

优先使用：

- 整数符号ID和整数状态机；
- 紧凑数组计数器；
- 缩放整数派奖；
- NumPy、Numba或等价编译/批量核心；
- Worker内不可变Runtime上下文；
- 每候选只构建一次的权重、alias/search表和条件缓存。

Python负责配置、分片、进程调度、checkpoint和最终合并。复杂状态机无法整体批量化时，至少使用固定数组和标量局部变量，不退回逐入口对象链。

## 分片与续跑

标准逻辑分片上限为`250000`个完整付费入口。它是seed、checkpoint和hash边界，不是必须填满的最小值：

- 10万初筛使用一个10万入口的短分片；
- 50万、200万和FORMAL档位按25万切分；
- 任一阶段最后不足25万时允许一个明确的尾分片；
- 分片起点和数量必须在运行前冻结，不能由Worker动态抢占后改变seed映射。

分片落点固定为：

| 阶段 | 路径 |
|---|---|
| BASELINE | `work/baseline/shards/shard-######.json` |
| CALIBRATION | `work/calibration/cv####/candidates/<candidate_id>/shards/shard-######.json` |
| 独立复核 | `work/candidate-freeze/<candidate_id>/independent-recheck/shards/shard-######.json` |
| FORMAL | `work/formal/fv####/shards/shard-######.json` |

每个文件必须通过`execution-shard.schema.json`。聚合结果和checkpoint保存在同一个分片文件中，不再建立另一套checkpoint目录或文件。

每个分片至少保存：

```text
shard_index
入口起点和数量
task_id、mode、rtp_group
合同hash
候选参数hash
Runtime bundle hash
模拟与观测脚本bundle hash
基础seed和实际分片seed
聚合测量
累计器checkpoint
输出hash
完成状态
```

Worker可在逻辑分片内使用更小micro-batch，但micro-batch大小不能改变RNG连续流、聚合结果、checkpoint或hash。

分片写入流程固定为：

1. 写同目录临时文件；
2. 完成JSON和输入指纹校验；
3. 删除`output_sha256`字段后，将对象按UTF-8、键名升序、无多余空白的JSON规范化序列化并计算SHA-256；
4. 原子替换正式分片文件；
5. 标记完成。

续跑时必须同时核对task、合同、候选、Runtime、脚本、seed、分片范围和输出hash。全部一致才允许跳过；任一不一致就重新计算该明确分片，不混合不同输入的聚合。

合并顺序固定为`shard_index_ascending`。

## Worker与并行

- `auto`默认最多使用逻辑CPU的70%，并至少给系统和聚合进程保留一个逻辑CPU。
- Worker不得超过逻辑CPU数，除非基准证明更高并发稳定提升吞吐并保存证据。
- 每个Worker只加载一次Runtime、规则、符号映射和只读查表，然后连续处理多个分片。
- 每个候选在每个Worker只构建一次候选上下文。
- 单次执行只允许一层主并行：候选级、分片级多进程、Numba parallel或BLAS/OpenMP线程池四选一。
- 使用多进程时，Worker内Numba、BLAS和OpenMP线程固定为1，禁止进程数乘线程数的嵌套超配。
- 单Worker和多Worker必须消费同一冻结分片计划。

## 执行前基准

正式大样本前先预热JIT和Worker，再分别测量“纯核心模拟”和“开启全部正式观测”：

```text
基准入口数
逻辑CPU和Worker数
预热/JIT策略
纯核心入口/秒
完整观测入口/秒
观测耗时增幅
每百万入口预计时间
FORMAL预计时间
每分片大小
预计峰值临时磁盘
checkpoint写入时间
中断续跑结果
```

基准用于发现并修复明显低效实现，不产生业务通过/不通过状态，也不能取消冻结样本计划。预计时间很长时报告耗时并继续执行。

## 等价验收

轻量观测器进入CALIBRATION或FORMAL前必须通过：

1. 与认证脚本逐入口投注、派奖、组件归属和状态语义一致；
2. 与完整观测器在同seed样本上逐入口语义事件一致；
3. 最终RNG状态一致；
4. 全部活动N/J/P/B原始测量一致，观察项清单与冻结合同一致；
5. 累计器结果一致；
6. 单Worker与多Worker一致；
7. 中断续跑与不中断整跑一致；
8. 不同micro-batch大小一致；
9. 短分片、完整25万分片和尾分片的seed映射一致；
10. Runtime能力矩阵中全部授权能力都可执行，未被固定数量检查缩窄；
11. 核心与完整观测吞吐已经记录，并处理可避免的明显低效点。

等价证据、脚本bundle hash、基准和续跑结果保存到`work/script-equivalence/comparisons/`或对应FORMAL目录，并由最终报告引用。
