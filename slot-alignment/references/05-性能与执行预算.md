## 样本量规划

CALIBRATION与FORMAL统一使用`assets/policies/sample_execution_policy.json`，并在候选出现前生成、校验和冻结`sample_execution_plan.json`。默认RNG协议为`chunk_seeded`；`crn_v1`只允许用于隔离的离线诊断，不得参与候选排序或FORMAL结论。

候选固定阶梯：

| 阶段 | 样本量 | 说明 |
|---|---:|---|
| 初筛 | `100000` | 全部候选 |
| 复筛 | 累计`500000` | 晋级候选 |
| 决赛 | 累计`2000000` | 决赛候选 |
| 独立复核 | 另跑`2000000` | 排名前2名，各自使用独立seed |

FORMAL固定档位为`10000000`、`20000000`、`50000000`。为每个活动条件指标实例记录原版条件暴露概率，该概率必须表示“一个完整付费入口是否进入此指标实例的整体有效分母”，不能使用分布内某个状态或桶的概率。单实例所需入口数为：

```text
ceil(2000 / 条件暴露概率)
```

取能覆盖全部活动条件实例的最小档位。若`50000000`仍无法让某些实例达到预计`2000`个有效样本，也不停止、不询问、不扩大到更高档：继续执行`50000000`，完成后把这些实例标为`样本不足/U`并在报告中列出实际有效样本。

以下额外样本要求全部禁止：每个稀有状态必须1000次、Feature周期必须100万次、某个P2状态必须2万次、独立追求RTP 99%半宽0.15个百分点。样本计划发生变化时，按合同冻结规则使既有结果失效，不得运行中静默改档。

## 两层观测

### 完整等价观测层

仅在有界、确定性小样本上生成完整逐入口账本，验证：

- RNG调用顺序和最终状态；
- 逐入口投注、总派奖和组件派奖；
- Feature、状态机、触发、重触发和结算语义；
- 盘面、中奖明细及守恒审计。

样本应覆盖全部玩法路径；自然样本不能稳定覆盖时使用额外确定性验证案例。不得为了“证据更完整”把该层直接扩展到全部CALIBRATION或FORMAL样本。

### 流式正式观测层

CALIBRATION和FORMAL使用已通过完整层验证的流式观测器。每个入口只在内存中存在一次，正式N/J/P/B计数立即累计，入口对象随后释放。逐RNG调用JSON、每局状态哈希和完整事件账本不得进入大样本热路径。

允许保存有界审计样本，但必须在计划中冻结抽样规则和上限，且不得改变RNG调用或正式指标结果。

## 大样本实现硬约束

- 单Worker内存复杂度为`O(1)`每入口，不随总入口数增长。
- 持久化文件数量为`O(分片数)`，不得为每入口创建文件或记录。
- 总入口数达到`100000`及以上时，禁止默认生成全量逐入口JSON/NDJSON。
- 禁止“逐局写盘 -> 全量读回 -> 聚合 -> 删除”的中间交换流程。
- 禁止在大样本热路径为每个随机点创建RNG对象，或为每局、每次RNG调用序列化参数、结果并计算独立hash。
- 禁止在热路径做Decimal字符串转换；派奖优先使用预先确定缩放倍率的整数累计，只在最终输出时转换。
- 禁止为了观测再次运行完整结算。优先让一次结算同时返回必要明细；若认证脚本接口不足，使用优化派生实现并完成等价验收。
- 正式指标不需要的审计字段不得进入每局热路径。
- 热路径优先使用整数符号ID、紧凑数组计数器和缩放整数派奖，避免字符串字典和短生命周期对象堆积。
- 聚合测量、累计器和报告事实必须保持与完整观测层一致。

## 分片与续跑

每个分片至少保存：

```text
shard index
入口起点与数量
task_id与mode/rtp_group
合同hash
候选参数hash
Runtime bundle hash
模拟与观测脚本bundle hash
基础种子与实际分片种子
聚合测量
累计器checkpoint
输出文件hash
完成状态
```

默认每个分片`250000`个完整付费入口。checkpoint只保存分片聚合、累计器和输入指纹，不保存逐局事件。使用临时文件写完后执行原子替换；半成品不得标记完成。重新启动时逐项验证输入指纹和输出hash，完全一致才跳过该分片。任一项不一致时重新计算该明确分片，不得混合不同合同、Runtime、脚本或种子的结果。

合并顺序固定为`shard_index_ascending`。单Worker与多Worker必须消费相同分片计划并得到完全相同的机器结果。

## Worker与资源预算

- `auto`默认不超过逻辑CPU的70%，并至少保留一个逻辑CPU给系统和聚合进程。
- Worker数不得超过逻辑CPU数；只有代表性基准证明更高并发稳定提升吞吐时才允许偏离默认值，并保存证据。
- 避免每个Worker内部再启动隐式多线程，防止进程数乘线程数造成超配。
- 每个Worker只加载一次Runtime、模型和只读查表，然后连续处理多个分片；禁止每个分片重复启动进程或重新解析完整配置。
- 分片大小固定为`250000`，保证候选、FORMAL、单/多Worker和续跑使用同一切分口径。

## 执行前基准与优化记录

正式大样本执行前运行代表性基准，至少记录：

```text
基准入口数
Worker数与逻辑CPU数
预热/JIT策略
入口/秒
每百万入口预计时间
FORMAL预计总时间
每分片文件大小
预计峰值临时磁盘
checkpoint与续跑验证结果
```

基准没有通过/不通过状态，不得阻止既定CALIBRATION或FORMAL执行。发现全量逐局磁盘I/O、逐RNG序列化、每随机点创建RNG、Decimal字符串转换、重复结算、Worker反复加载Runtime或无法续跑时，应先做可实现的热路径优化并重新记录基准；仍需较长时间时在进度信息中说明预计耗时，但继续按冻结样本计划执行。

## 等价验收

轻量观测器投入CALIBRATION或FORMAL前必须全部通过：

1. 与认证脚本逐入口投注、派奖、组件归属和状态语义一致。
2. 与完整观测器在同种子样本上逐入口语义事件一致。
3. 完整观测器与轻量观测器结束后的RNG状态一致。
4. 全部正式N/J/P/B原始测量及审计聚合一致。
5. 模拟累计器一致。
6. 单Worker与多Worker结果一致。
7. 中断后续跑与不中断整跑结果一致。
8. 性能基准已记录，且已处理可避免的明显低效实现；该项不产生阻塞门禁。

把等价结果、脚本bundle hash、基准结果和续跑结果保存在任务`work/script-equivalence/comparisons/`或对应FORMAL过程目录，并在最终FORMAL可信性证据中引用。
