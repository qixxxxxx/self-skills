# 阶段 3：评分系统

## 两层判定

先判硬指标红线，再计算非硬指标分数。硬指标不能被综合分抵消。

### 硬指标

使用 Owner 的`hard_gate_profile`比较目标、候选、容差、置信资格和边界。输出`通过`、`不通过`、`硬指标已豁免`、原始差距、归一化差距和证据；权重恒为 0。

### 非硬指标

使用 Owner 的`score_profile`把归一化差距映射为 0～100。锚点间线性插值，区间外截断到 0 或 100；判定使用未舍入值。

有序分布评分必须使用阶段2已密封的`ordered_distance_policy`。评分器只执行合同中的真实桶位置、轴语义、变换和尺度，不得根据基线或候选最大值自动换轴；政策来源字段、活动实例清单或hash不一致时评分无效。

使用总变差、一维Wasserstein、分组版本或概率残差评价的活动指标，还必须通过阶段2已密封的`sample_capability_policy`。原版目标样本和FORMAL计划样本分别按99%置信度检查，条件指标逐活动组检查；缺任一指标或组的样本能力、政策hash失效或任一侧不足，都属于“样本不足”并使评分无法判定，不能按0分或不适用处理。

五档固定为：

| 分数 | 档位 |
|---:|---|
| ≥95 | 高度对齐 |
| ≥85 | 对齐通过 |
| ≥70 | 轻度偏差 |
| ≥50 | 明显偏差 |
| <50 | 严重偏差 |

单项 85 分表示该项自身通过；综合分 80 分表示整体体验通过，两者不能互相替代。

## 综合分

使用密封的分层权重树。每项只有一个计分归属；硬指标、审计、诊断和重复引用权重为 0。同一`score_budget_key`的多个作用域实例先按显式`scope_weight`和`scope_aggregation`汇总为一个`budget_score`，再以一次显式指标`weight`进入评分组，最后由顶层`group_weights`汇总综合分。新任务的顶层权重必须由`score_group_weight_policy.v1.json`按活动语义组基础预算确定性生成，不能按指标数、作用域数或候选频率分配。活动评分组键必须完全一致且权重合计为1；运行时不得为缺失的作用域、指标或评分组权重静默补1。`不适用`和用户批准的`已豁免`在候选出现前先移出活动组，再按政策重新归一化。

`缺失`、`样本不足`、`计算异常`和`缺口`不重分配，直接使评分无效。所有有效非硬指标消失时显示`无有效评分`，不得给 100。

审计指标不进入综合分，但必须写入`scorecard.audits`。`audit_profile.blocking_on_missing=true`的审计缺失或无效时直接阻塞；`blocking_on_mismatch=true`且测量状态不等于`required_result_status`时同样阻塞。低频审计可按目录声明输出`置信不足`且不阻塞，但不得伪装为“符合”。

## 最终状态

1. 数据门禁或评分资格无效：`无法判定`。
2. 任一未豁免硬指标失败：`不通过`。
3. 综合分不存在或低于 80：`不通过`。
4. 条件满足且存在必需豁免：`豁免后通过`。
5. 条件满足且无豁免：`通过`。

## 固定输出

```text
artifacts/03-scoring/
├── scorecard.json
└── stage3_gate.json

<report_dir>/
└── 阶段3-评分报告.md
```

`scorecard.json`必须由当前基线测量生成并保存逐作用域`scores`、按预算键聚合的`budget_scores`、评分组、样本能力政策摘要、指标合同、测量源路径及SHA-256。Markdown必须由`render_scoring_report.py`根据当前合同和scorecard确定性生成；逐项展示原版与FORMAL计划样本能力，不得手写或使用候选内部scorecard替代。

阶段3中文报告严格使用10章模板及逐章展示实例；硬指标、评分组、逐项评分、低分项和门禁表的表头名称与顺序不得变化。除评分结果外，还必须呈现冻结输入、评价方法/锚点、三级容差、阻塞/豁免、覆盖率复核、复算hash和阶段3到4门禁。

## 阶段3到阶段4门禁

阶段3基线状态可以是`通过`、`豁免后通过`或`不通过`；`不通过`表示需要进入阶段4调参，不是阶段转换失败。只有`无法判定`、存在阻塞、指标数量与合同不一致、测量源失效、合同hash变化、中文报告非确定性输出或固定产物缺失时，才阻止阶段4。

生成报告后必须运行`validate_stage_transition.py`并得到`stage3_gate.json`：`status=通过`且`stage4_allowed=true`。在此之前禁止执行敏感性、CALIBRATION、候选计算或创建阶段4批次目录。自动连续执行只免除用户逐阶段确认，不免除固定产物和机器门禁。
