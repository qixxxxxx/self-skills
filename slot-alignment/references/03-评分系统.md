# 阶段 3：评分系统

## 两层判定

先判硬指标红线，再计算非硬指标分数。硬指标不能被综合分抵消。

### 硬指标

使用 Owner 的`hard_gate_profile`比较目标、候选、容差、置信资格和边界。输出`通过`、`不通过`、`硬指标已豁免`、原始差距、归一化差距和证据；权重恒为 0。

### 非硬指标

使用 Owner 的`score_profile`把归一化差距映射为 0～100。锚点间线性插值，区间外截断到 0 或 100；判定使用未舍入值。

五档固定为：

| 分数 | 档位 |
|---:|---|
| ≥95 | 高度对齐 |
| ≥85 | 对齐通过 |
| ≥70 | 轻度偏差 |
| ≥50 | 明显偏差 |
| <50 | 严重偏差 |

单项 85 分表示该项自身通过；综合分 80 分表示整体体验通过，两者不能互相替代。

## 综合分

使用密封的分层权重树。每项只有一个计分归属；硬指标、审计、诊断和重复引用权重为 0。`不适用`和用户批准的`已豁免`按同父级剩余原权重比例重归一化。

`缺失`、`样本不足`、`计算异常`和`缺口`不重分配，直接使评分无效。所有有效非硬指标消失时显示`无有效评分`，不得给 100。

## 最终状态

1. 数据门禁或评分资格无效：`无法判定`。
2. 任一未豁免硬指标失败：`不通过`。
3. 综合分不存在或低于 80：`不通过`。
4. 条件满足且存在必需豁免：`豁免后通过`。
5. 条件满足且无豁免：`通过`。

## 固定输出

```text
artifacts/03-scoring/
├── scorecard.json
└── 阶段3-评分报告.md
```

Markdown 必须由机器结果生成。相同输入必须产生相同 JSON；展示舍入不得改变判定。
