# 阶段 4：自动对齐与 FORMAL

## 生命周期

0. **阶段转换**：读取`artifacts/03-scoring/stage3_gate.json`，只有`status=通过`且`stage4_allowed=true`才能启动本阶段。
1. **基线继承**：使用阶段3已密封的当前 Runtime 基线；已达标则直接冻结，不为追求更高分增加变更。
2. **敏感性**：按控制簇做低成本合法扰动，确认参数生效、方向、耦合和局部有效秩。
3. **CALIBRATION**：在授权空间内使用安全漏斗搜索。
4. **候选冻结**：保存不可变候选 ID、完整参数、父候选、输入 hash、样本范围和评分。
5. **FORMAL**：使用预先密封且与 CALIBRATION 完全独立的新种子、新样本验收。

优化采用字典序：未豁免硬指标全部通过 → 综合分最高且至少 80 → 参数变化最小 → 长尾及运行风险最低。不得用后项补偿前项。

## 搜索边界

阶段4所有候选必须记录`stage3_gate.json`的SHA-256。门禁文件或其任一上游hash变化时，已有阶段4候选全部失效并退回阶段3重新评分和生成报告。

只修改授权参数并保持合法约束、归一化和依赖关系。候选实际改变模式、玩法、游戏逻辑、状态机、RNG、结算语义、付费配置或配置结构时立即淘汰并退回阶段1/2修正搜索实现；若指标在全部合法候选中只有越过这些边界才能完成，密封结构不可达证据并自动豁免对应精确实例，不询问用户。

同轮候选使用共同随机种子比较；FORMAL 必须换用独立种子。CALIBRATION 结果不得并入 FORMAL，也不得用 FORMAL 结果训练搜索模型。

敏感性、CALIBRATION四级样本和FORMAL的每个候选默认使用单候选内部样本分片并行。假设该候选预算为N个完整付费入口、实际使用W个Worker，则把同一N个入口拆成W个不重叠分片执行，合并后仍只计N个入口；不得把每个Worker都运行N个入口，不得同时并行多个候选，也不得建立嵌套进程池。Worker数变化不产生新候选、不改变种子集，也不构成FORMAL独立性。

## FORMAL

- 每个冻结候选绑定一套查看结果前密封的 FORMAL 计划。
- FORMAL只通过`python_bin`执行阶段1用户认证的原始`.py`脚本或已通过自动等价门禁的观测/输出派生脚本，并同时绑定用户认证证据hash、实际执行脚本hash及适用的等价证据hash；CALIBRATION与FORMAL使用同一合格执行脚本，不设置服务端对照节点。
- FORMAL必须输出`sample.metric_sample_counts`，逐一覆盖样本能力政策中的全部活动指标实例；条件指标必须同时给出完整`group_sample_counts`。验收时使用这些实际值逐指标、逐组重新计算99%样本能力，禁止把阶段2计划样本数当作实际值。
- 实际样本不足持续按增量批次自动扩样；形成结构不可达证据时，自动豁免对应精确实例并重生成阶段3/4结果。缺少计数或条件组结构错误属于输出实现错误，不得直接按样本不足豁免；若修复必然要求越过禁止变更边界，则按结构不可达豁免。
- 统计失败永久标记当前候选失败，自动返回 CALIBRATION 创建新候选；不得只换种子重试同一候选，也不得中途询问用户是否继续。
- 执行链异常修复后可按原计划重跑，不计入有效尝试。
- FORMAL有效尝试不设固定候选次数上限；失败后持续返回CALIBRATION生成不同冻结候选，直到通过或形成结构不可达证据。
- CALIBRATION与FORMAL预算自动追加，不以预算耗尽结束，也不请求用户批准预算；结构不可达证据有效时停止预算扩张、豁免证据列出的实例并退回阶段3重生成评分。预算消耗本身不得冒充结构不可达证据。
- FORMAL计划必须在查看结果前密封总入口数、全局入口编号范围、分片计划、默认Worker政策和合并顺序。FORMAL独立性只由冻结候选、独立种子和独立样本计划决定；Worker编号、Worker数量和调度顺序不得参与RNG或独立性判定。
- 分片结果必须按`shard_index`升序合并原始累加器，再统一计算RTP、方差、分布和派生指标；禁止平均各Worker已经计算出的最终RTP、Sigma、分位数或评分。Worker失败只重跑原分片，不扩大或替换样本范围。
- 完整交付前，Runtime、脚本、指标库、合同、豁免、作用域或计划变化时，候选和结果自动失效。观测/输出派生脚本变化时退回阶段1自动重跑等价门禁并修复差异，不等待用户重新认证；原始认证脚本hash变化才表示认证事实源已改变并阻塞使用旧认证。

模板中的每一章均为展示契约，并提供固定Markdown实例：实际报告必须采用相同展示类型、字段名与字段顺序。必须展示RTP置信区间、分布桶与容差系数、Sigma、组件占比映射、评分及低分项、玩法覆盖、长尾、逐参数变化、预算与可达性上限、候选晋退、停止原因、逐指标及逐组FORMAL实际样本能力、FORMAL计划/结果/独立性、豁免阻塞、交付建议和全部hash。
