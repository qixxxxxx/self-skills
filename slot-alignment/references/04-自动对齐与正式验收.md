# 阶段 4：自动对齐与 FORMAL

## 生命周期

1. **基线**：用当前 Runtime 测量；已达标则直接冻结，不为追求更高分增加变更。
2. **敏感性**：按控制簇做低成本合法扰动，确认参数生效、方向、耦合和局部有效秩。
3. **CALIBRATION**：在授权空间内使用安全漏斗搜索。
4. **候选冻结**：保存不可变候选 ID、完整参数、父候选、输入 hash、样本范围和评分。
5. **FORMAL**：使用预先密封且与 CALIBRATION 完全独立的新种子、新样本验收。

优化采用字典序：未豁免硬指标全部通过 → 综合分最高且至少 80 → 参数变化最小 → 长尾及运行风险最低。不得用后项补偿前项。

## 搜索边界

只修改授权参数并保持合法约束、归一化和依赖关系。参数未生效、控制方向与预检相反或游戏逻辑变化时立即隔离结果并退回阶段 1/2。

同轮候选使用共同随机种子比较；FORMAL 必须换用独立种子。CALIBRATION 结果不得并入 FORMAL，也不得用 FORMAL 结果训练搜索模型。

## FORMAL

- 每个冻结候选绑定一套查看结果前密封的 FORMAL 计划。
- 统计失败永久标记当前候选失败，返回 CALIBRATION 创建新候选；不得只换种子重试同一候选。
- 执行链异常修复后可按原计划重跑，不计入有效尝试。
- 默认最多 3 个不同冻结候选的有效 FORMAL 尝试。
- Runtime、server、脚本、指标库、合同、豁免、作用域或计划变化时，候选和结果自动失效。
