# 确定性工具与验证

## 使用规则

- 全部Python命令使用任务解析出的`python_bin`。
- `<skill_root>`是当前`slot-alignment`目录；`<artifacts>`是任务根目录下的`artifacts/`。
- 阶段机器JSON是权威事实，报告只由对应生成器输出。
- 先运行上游生成或政策脚本，再运行语义、阶段转换和交付校验。
- 历史任务只有受支持的密封版本可添加`--historical-replay`；新任务禁止使用该参数。
- `render_post_delivery_server_flow_report.py`仅为历史只读兼容资源，不属于新任务命令链。

## 目录维护

目录JSON发生变化后依次运行：

```bash
<python_bin> <skill_root>/scripts/generate_metric_summary.py --skill-root <skill_root>
<python_bin> <skill_root>/scripts/catalog_tool.py validate --skill-root <skill_root>
<python_bin> <skill_root>/scripts/catalog_tool.py hash --skill-root <skill_root>
```

`generate_metric_summary.py`会写入`references/指标目录/指标汇总.md`；其余两个命令只读校验或输出hash。

## 开工前与阶段1

先编译画像对应的指标实例和统计能力：

```bash
<python_bin> <skill_root>/scripts/compile_metric_instances.py \
  --game-profile <artifacts/01-input-profile/game_profile.json> \
  --input-manifest <artifacts/01-input-profile/input_manifest.json> \
  --task-root <task_root> \
  [--measurement-capabilities <measurement_capabilities.json>] \
  --output <metric_instance_plan.json> \
  --extension-proposal <metric_extension_proposal.json>
```

若需要增强观测或输出，保留用户认证原始脚本只读，使用相同种子分别生成规范化语义快照。快照至少包含`script_sha256`、`seed_set_sha256`、`rng_call_sequence_sha256`、`semantic_entries`、`total_rtp`、`component_rtp`和`key_metrics`，然后运行：

```bash
<python_bin> <skill_root>/scripts/validate_script_equivalence.py \
  --certified <work/script-equivalence/certified/semantic_snapshot.json> \
  --execution <work/script-equivalence/derived/semantic_snapshot.json> \
  --output <work/script-equivalence/script_equivalence.json>
```

返回`不通过`时必须读取`differences`，仅修正观测/输出派生实现并重新生成快照、重跑本命令；不得请求用户重新认证。通过后把结果及其hash写入`input_manifest.script_qualification.script_equivalence`。

阶段1机器JSON齐全后生成中文报告：

```bash
<python_bin> <skill_root>/scripts/render_input_profile_report.py \
  --artifacts <artifacts> \
  --output <report_dir>/阶段1-资料确认与玩法画像.md
```

## 阶段2政策链

组件RTP目标按原版贡献占比映射权威总RTP：

```bash
<python_bin> <skill_root>/scripts/derive_component_rtp_targets.py \
  --input <component_rtp_shares.json> \
  --output <component_rtp_targets.json>
```

展开1.3合同完成适用性、退化和已批准豁免判定后，严格按顺序运行：

```bash
<python_bin> <skill_root>/scripts/apply_hard_gate_tolerance_policy.py \
  --contract <base_metric_contract.json> \
  --policy <skill_root>/assets/policies/hard_gate_tolerance_policy.v2.json \
  --output <tolerance_metric_contract.json>

<python_bin> <skill_root>/scripts/apply_jackpot_materiality_policy.py \
  --contract <tolerance_metric_contract.json> \
  --game-profile <artifacts/01-input-profile/game_profile.json> \
  --policy <skill_root>/assets/policies/jackpot_materiality_policy.v1.json \
  --output <jackpot_metric_contract.json>

<python_bin> <skill_root>/scripts/apply_ordered_distance_policy.py \
  --contract <jackpot_metric_contract.json> \
  --policy <skill_root>/assets/policies/ordered_distance_policy.v1.json \
  --output <ordered_metric_contract.json>

<python_bin> <skill_root>/scripts/apply_score_group_weight_policy.py \
  --contract <ordered_metric_contract.json> \
  --policy <skill_root>/assets/policies/score_group_weight_policy.v1.json \
  --output <weighted_metric_contract.json>

<python_bin> <skill_root>/scripts/apply_sample_capability_policy.py \
  --contract <weighted_metric_contract.json> \
  --policy <skill_root>/assets/policies/sample_capability_policy.v1.json \
  --automatic-waiver-policy <skill_root>/assets/policies/automatic_metric_waiver_policy.v1.json \
  --output <sampled_metric_contract.json>
```

阶段4形成结构不可达证据，或FORMAL实际样本仍不足时，分别运行：

```bash
<python_bin> <skill_root>/scripts/apply_automatic_waiver_policy.py \
  --contract <metric_contract.json> \
  --policy <skill_root>/assets/policies/automatic_metric_waiver_policy.v1.json \
  --source structural-unattainability \
  --attainability-evidence <attainability_evidence.json> \
  --output <metric_contract.json>

<python_bin> <skill_root>/scripts/apply_automatic_waiver_policy.py \
  --contract <metric_contract.json> \
  --policy <skill_root>/assets/policies/automatic_metric_waiver_policy.v1.json \
  --source formal-sample-capability \
  --formal-result <formal_result.json> \
  --output <metric_contract.json>
```

政策链完成后，把展开1.3合同紧凑化为阶段2固定1.4产物：

```bash
<python_bin> <skill_root>/scripts/compact_metric_contract.py \
  --contract <metric_contract_1.3.json> \
  --output <artifacts/02-metric-matching/metric_contract.json>
```

随后生成报告并执行动态语义门禁：

```bash
<python_bin> <skill_root>/scripts/render_metric_matching_report.py \
  --contract <artifacts/02-metric-matching/metric_contract.json> \
  [--display-metadata <report_display_metadata.json>] \
  --output <report_dir>/阶段2-指标匹配报告.md

<python_bin> <skill_root>/scripts/semantic_contract_validation.py \
  --input-manifest <artifacts/01-input-profile/input_manifest.json> \
  --game-profile <artifacts/01-input-profile/game_profile.json> \
  --parameter-authority <artifacts/01-input-profile/parameter_authority.json> \
  --metric-contract <artifacts/02-metric-matching/metric_contract.json> \

```


## FORMAL前、交付与最终验证

阶段4完成后先做预交付验证：

```bash
<python_bin> <skill_root>/scripts/validate_artifacts.py \
  --artifacts <artifacts> \
  --reports <report_dir> \
  --pre-delivery
```

通过后封存交付，再执行完整验证：

```bash
<python_bin> <skill_root>/scripts/seal_delivery.py \
  --artifacts <artifacts> \
  --reports <report_dir> \
  --formal-runtime <formal_runtime>

<python_bin> <skill_root>/scripts/validate_artifacts.py \
  --artifacts <artifacts> \
  --reports <report_dir>
```

Skill自身重构或目录维护完成后运行：

```bash
<python_bin> <skill_root>/scripts/self_test.py
```

若需要校验Skill元数据和基础目录结构，再运行`skill-creator/scripts/quick_validate.py <skill_root>`。
