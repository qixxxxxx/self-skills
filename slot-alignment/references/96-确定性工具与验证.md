# 确定性工具与验证

## 使用规则

- 全部Python命令使用任务解析出的`python_bin`。
- `<skill_root>`是当前`slot-alignment`目录；`<artifacts>`是任务根目录下的`artifacts/`。
- 阶段机器JSON是权威事实，报告只由对应生成器输出。
- 先运行上游生成或政策脚本，再运行语义、阶段转换和交付校验。
- 历史任务只有受支持的密封版本可添加`--historical-replay`；新任务禁止使用该参数。
- `render_post_delivery_server_flow_report.py`仅为历史只读兼容资源，不属于新任务命令链。

## 目录维护

目录JSON发生变化后依次运行：

```bash
<python_bin> <skill_root>/scripts/generate_metric_summary.py --skill-root <skill_root>
<python_bin> <skill_root>/scripts/catalog_tool.py validate --skill-root <skill_root>
<python_bin> <skill_root>/scripts/catalog_tool.py hash --skill-root <skill_root>
```

`generate_metric_summary.py`会写入`references/指标目录/指标汇总.md`；其余两个命令只读校验或输出hash。

## 开工前与阶段1

先编译画像对应的指标实例和统计能力：

```bash
<python_bin> <skill_root>/scripts/compile_metric_instances.py \
  --game-profile <artifacts/01-input-profile/game_profile.json> \
  --input-manifest <artifacts/01-input-profile/input_manifest.json> \
  --task-root <task_root> \
  [--measurement-capabilities <measurement_capabilities.json>] \
  --output <metric_instance_plan.json> \
  --extension-proposal <metric_extension_proposal.json>
```

用户在第一次preflight选择全量重算后，处理全部`all_discovered_sources`。处理源数、最终入口数、结果路径和SHA-256均有效时，直接写入：

```text
recount_status=已完成
effective_entry_count=recounted_entry_count
final_count_adoption_method=automatic_full_recount
auto_adopted_entry_count=recounted_entry_count
```

随后继续阶段1，不再请求用户确认最终入口数。仅在处理源不完整、数量无效、结果路径缺失或SHA-256无效时阻塞。

若需要增强观测或输出，保留用户认证原始脚本只读，使用相同种子分别生成规范化语义快照。快照至少包含`script_sha256`、`seed_set_sha256`、`rng_call_sequence_sha256`、`semantic_entries`、`total_rtp`、`component_rtp`和`key_metrics`，然后运行：

```bash
<python_bin> <skill_root>/scripts/validate_script_equivalence.py \
  --certified <work/script-equivalence/certified/semantic_snapshot.json> \
  --execution <work/script-equivalence/derived/semantic_snapshot.json> \
  --output <work/script-equivalence/script_equivalence.json>
```

返回`不通过`时必须读取`differences`，仅修正观测/输出派生实现并重新生成快照、重跑本命令；不得请求用户重新认证。通过后把结果及其hash写入`input_manifest.script_qualification.script_equivalence`。

阶段1机器JSON齐全后生成中文报告：

```bash
<python_bin> <skill_root>/scripts/render_input_profile_report.py \
  --artifacts <artifacts> \
  --output <report_dir>/阶段1-资料确认与玩法画像.md
```

## 阶段3评分与转换

```bash
<python_bin> <skill_root>/scripts/score_alignment.py \
  --contract <artifacts/02-metric-matching/metric_contract.json> \
  --measurements <measurements.json> \
  --output <artifacts/03-scoring/scorecard.json>

<python_bin> <skill_root>/scripts/render_scoring_report.py \
  --contract <artifacts/02-metric-matching/metric_contract.json> \
  --scorecard <artifacts/03-scoring/scorecard.json> \
  [--display-metadata <report_display_metadata.json>] \
  --output <report_dir>/阶段3-评分报告.md

<python_bin> <skill_root>/scripts/validate_stage_transition.py \
  --artifacts <artifacts> \
  --reports <report_dir> \
  --output <artifacts/03-scoring/stage3_gate.json>
```

只有`stage3_gate.json.status=通过`且`stage4_allowed=true`才能开始阶段4。

新任务阶段4必须把`continuous_execution_policy.v2.json`及其SHA-256完整密封到`alignment_manifest.execution_policy`，并把`parallel_execution_policy.v1.json`及其SHA-256密封到`alignment_manifest.execution_policy.parallel_execution`。每批预算在查看该批结果前密封；当前批次消耗完成后自动创建下一批，不设置整体预算或FORMAL候选次数上限。循环只在FORMAL通过或结构不可达证据通过Schema与Hash校验后结束。

为单个候选生成默认并行分片计划：

```bash
<python_bin> <skill_root>/scripts/parallel_execution.py \
  --total-entries 100000 \
  --workers auto \
  --output <work>/parallel-plans/<plan_id>.json
```

`auto`固定按`max(1, floor(进程可用逻辑核心数 × 70%))`解析。任务专用模拟器和搜索脚本必须接受`--workers auto|N`，读取同一密封计划，按全局入口编号运行各分片，并按`shard_index`升序合并原始累加器。不得直接调用绕过该入口的单线程`base_metrics()`类函数。

正式采用多Worker前，使用同一份已密封分片计划分别执行：

```bash
<python_bin> <task_simulator.py> --shard-plan <parallel_plan.json> --workers 1 --output <single_worker.json>
<python_bin> <task_simulator.py> --shard-plan <parallel_plan.json> --workers auto --output <auto_worker.json>
```

自动比较RNG语义hash、逐分片原始累加器、合并后累加器和最终指标；全部等价才允许用于CALIBRATION确认或FORMAL。失败时自动读取差异，修正分片、RNG定位或合并实现并重验，不请求用户批准，也不得靠改变总样本数或种子集消除差异。实际Worker数、可用核心数、政策hash、分片计划hash、合并顺序和等价证据hash写入候选批次与FORMAL机器证据。

## FORMAL前、交付与最终验证

阶段4完成后先做预交付验证：

```bash
<python_bin> <skill_root>/scripts/validate_artifacts.py \
  --artifacts <artifacts> \
  --reports <report_dir> \
  --pre-delivery
```

通过后封存交付，再执行完整验证：

```bash
<python_bin> <skill_root>/scripts/seal_delivery.py \
  --artifacts <artifacts> \
  --reports <report_dir> \
  --formal-runtime <formal_runtime>

<python_bin> <skill_root>/scripts/validate_artifacts.py \
  --artifacts <artifacts> \
  --reports <report_dir>
```

Skill自身重构或目录维护完成后运行：

```bash
<python_bin> <skill_root>/scripts/self_test.py
```

若需要校验Skill元数据和基础目录结构，再运行`skill-creator/scripts/quick_validate.py <skill_root>`。
