# 阶段 3A：指标评价合同

## 必需字段

每个指标实例必须包含：`metric_id`、Owner、类型、作用域、目标、测量单位、样本单位、条件分母、归一化口径、数据源、样本资格、状态、控制簇、语义角色、指标关系、评价合同、`score_budget_key`、作用域聚合方式、计分归属、版本与 hash。合同顶层`scope.mode_contract`必须与阶段1完全一致，保证整个指标集合只属于一个固定Feature选择和一个固定付费配置。

凡评价方法属于总变差、一维Wasserstein、分组总变差、分组一维Wasserstein、平均绝对概率残差或其分组版本，还必须保存`sample_capability_input`与政策确定性生成的`sample_capability`。非分组指标分别记录原版与FORMAL计划总样本；分组指标还要逐活动组记录样本并与总数守恒。合同必须展示每侧所需、实际、缺口和状态，FORMAL再用实际`metric_sample_counts`逐指标逐组复验；计划值不得冒充实际值。

Normal、Ante、Bonus Bet、增强投注或其他付费配置必须使用逐完整付费入口的实际经济扣款作为RTP、回报、贡献和反事实增量RTP的分母。Normal基础投注额只可作为明确标记的阅读换算，不得替代增强配置的实际成本；跨配置混样、先混合再按平均投注归一或在同一FORMAL批次内切换配置都使合同无效。

通用作用域维度`state`必须是候选结果生成前已知、由画像密封且会改变数学分布的前置状态；同一`component × board_phase`中的状态值必须互斥、完备。不得用中奖结果、回报档位、最终Cascade深度、目标指标字段或其他结果后信息切分作用域；已有步骤、层级、入口来源等专用维度时，不得把同一变量再次复制成`state`增加实例权重。

`hard_gate_profile`至少定义：比较方法、基础容差、容差系数、生效容差、政策 ID、方向、置信规则、边界包含方式、近零处理和差距输出。新任务的详细系数规则见`03B-硬指标容差系数.md`。

`audit_profile`至少定义审计方法和缺失是否阻塞。规则一致性审计还必须定义`blocking_on_mismatch=true`与`required_result_status`；`field_consistency_gate`除核对顶层状态外，还必须验证目标对象字段齐全，拒绝任何`*_status`字段与目标不一致、为“不符合”或“无法证明”的自相矛盾结果。规则数值需要逐项相等时必须在`exact_match_fields`中明确列出，不能把样本观测字段一起误设为精确相等。低频统计审计若允许样本不足不阻塞，必须显式定义`insufficient_sample_status`和`insufficient_sample_blocks_formal=false`。阶段3和FORMAL都要输出逐项审计状态，不能因为审计不计分而跳过测量。

`score_profile`至少定义：距离方法、方向、近零处理、样本资格和按差距从小到大排列的分数锚点，例如：

```json
{
  "method": "relative_error",
  "anchors": [
    {"distance": 0.0, "score": 100},
    {"distance": 0.03, "score": 95},
    {"distance": 0.08, "score": 85},
    {"distance": 0.15, "score": 70},
    {"distance": 0.30, "score": 50},
    {"distance": 1.00, "score": 0}
  ]
}
```

公共目录只定义方法和默认政策；游戏专属目标从权威规格或密封原版证据解析到`metric_contract.json`。缺少目标或方法均视为指标缺口，运行时不得补猜。

组件 RTP 指标必须额外保存`target_derivation`：方法固定为`original_component_share_mapped_to_authoritative_total_rtp`，记录原版贡献占比、原版证据及权威总 RTP 目标。不得把原版组件绝对 RTP 写入`target`。

## 支持的距离

- `absolute_error`：`abs(candidate-target)`。
- `relative_error`：`abs(candidate-target)/max(abs(target), zero_floor)`。
- `range_error`：候选在目标区间内为 0，区间外取到最近边界的距离。
- `total_variation`：离散分布的`0.5 * Σ|p-q|`。
- `mean_absolute_error`：同结构数值数组或对象逐项取绝对差后求平均；适合各项本身都是概率、但整组不要求合计为1的向量。
- `max_absolute_error`：同结构数值数组或对象逐项绝对差的最大值；适合集中度等任一字段严重偏离都需要显著扣分的对象。
- `grouped_mean_absolute_error`：对象字段使用`组ID::字段`表达，每组先对字段绝对差取平均，再按候选出现前写入任务合同的`group_weights`加权；适合每个条件组内都是有符号概率残差、字段数可能不同且不应让稀有组或字段较多的组自然增权的Interaction。公共目录只声明`group_separator`、`group_weight_source=task_contract`和`normalization_tolerance`，实际组权重只能写入任务合同。每个活动组权重必须是有限正数、全部活动组权重合计为1，且不得使用候选频率。
- 多格符号变形的目标一致性残差使用`grouped_mean_absolute_error`，组键固定为真实`changed_count|source_a+source_b`，字段固定为`same_target_residual`。每个事件先等权计算组内同目标率，再减去候选自身`P(target|source)`边际给出的独立基线；无序来源对按画像`source_domain`顺序规范化，残差必须落在`[-1,1]`，组权重来自密封原版事件暴露，禁止按格对数量或候选频率加权。
- `grouped_total_variation`：对象字段使用`组ID::档位`表达，每组分别归一化并计算总变差，再按候选出现前写入任务合同的`group_weights`加权；适合每种符号各自拥有一套无序类别分布。每个已列入组的权重必须是有限正数、全部组权重合计为1，且不得取候选频率。
- `wasserstein_1d`：先把原版和候选有序分布归一化，再按合同中严格递增的真实`bin_positions`计算一维Wasserstein距离。次数、长度、占格数等自然线性量使用`position_transform=identity`并除以`sealed_support_span`；回报、奖值、倍率和组合容量等非负长尾量使用政策固定的`position_transform=log10_1p`，即先变换为`log10(1+x)`，再以`distance_normalization=fixed_transform_unit`、`distance_scale=1`和`distance_unit=log10_decade`计距。缺少已密封实际位置时阻塞，不能用桶编号代替业务位置。
- `grouped_wasserstein_1d`：对象字段使用`组ID::实际档位`表达，每个条件组按任务合同中的`bin_positions_by_group`及目录固定的位置变换独立计算，再按候选出现前密封的`group_weights`加权。每个已列入组的权重必须是有限正数、全部组权重合计为1，且禁止使用候选频率；适合“给定符号后的实际中奖规模”“给定容量后的回报”等条件有序分布。

数组和对象必须具有相同字段、桶定义、单位和归一化口径；否则评分阻塞。`total_variation`的原版与候选必须各自归一化为1；`grouped_total_variation`与`grouped_wasserstein_1d`的每个组必须归一化为1。非归一概率向量不得冒用总变差。

长尾位置变换由`ordered_distance_policy.v1.json`和公共指标语义固定，任务执行者不得依据候选结果、样本最大值或期望得分切换。`log10_1p`只接受有限非负实际位置：0保持0，较大的倍率与奖值按数量级比较；距离0.05表示约5%的概率质量移动一个完整十倍级，且双方概率均为0的新极端桶不会改变距离。金额必须先换算到声明经济分母下的倍数。若业务轴允许负值、混合单位或无法证明同量纲有序位置，停止并提出指标扩展，不能临时改用绝对值或桶编号。

Collect输出、中奖规模和有序持久状态属于动态轴语义，但“动态”只表示由玩法画像解析，不表示运行时可选。直接派奖/倍率结果使用`nonnegative_multiplicative`；状态增量、等级、自然计数和进度使用`natural_linear`；Ways实际中奖组合数使用前者，线数、连中轴数、Count Pay数量和Cluster格数使用后者；同一持久状态的值分布和转移分布必须同轴。

## 退化支持集

阶段2必须根据候选出现前的规格、原版证据和结构可达性，在任务合同中密封评分分布的有效可达支持；不得把“原版样本本次未出现”猜成结构不可达。适用的分布评分指标在`score_profile`中写入`reachable_support_source=task_contract`和`reachable_support_status=active`，目标只保留结构可达项，并且有效支持至少包含2项。

分组指标只保留有效支持至少2项的活动组；`group_weights`只能覆盖这些活动组，使用原版密封权重重新归一化，不能保留退化组、0权重组或候选频率权重。部分组退化时只移除对应组；全部组退化或非分组指标只有一个结构可达结果时，指标必须写为`status=不适用`、`inapplicability_reason_code=degenerate_reachable_support`及`reachable_support_status=all_degenerate`，保留规则一致性证据，但不生成评分预算、不得得到常量100分。

## 语义角色与派生关系

- `primary`：唯一正式评分Owner，可进入综合分。
- `guard_cross_check`：业务红线或守恒交叉核对，通常是硬门禁，不进入综合分。
- `derived_diagnostic`：可由其他密封指标精确推导，只用于审计和中文摘要，权重固定为0。
- `audit`：低频、规则或边界核对，不进入综合分。

`relationships.derived_from`或`marginal_of`非空的指标不得设为评分项。联合分布若与自身可复算的同事件子集边际同时评分，必须把联合项改为条件分布、依赖残差或审计，否则视为重复Owner。稳定对象移动按数量转移分组评价纯配对残差：实际起点终点联合量减去在相同结构支持上保持候选自身起点与终点边际的最大熵基线。该残差只拥有配对耦合；移除/新增数量、绑定前后位置份额和位置角色偏向继续由各自主Owner负责。

条件Owner派生必须在候选出现前密封原始画像绑定、来源指标实例、来源目标证据hash、确定规则和唯一方向。动态奖值与生效倍率只有在`value_symbol_effective_multiplier_binding`全部严格成立时适用：符号赋值实例与倍率应用事件同域双向一一对应、每个赋值恰好兑现一次、没有额外倍率源、实际值支持完整且双向确定映射、`rule_evidence_sha256`有效。`primary_owner_metric_id`指定的指标保持活动，另一项才可标记`deterministically_derived_from_primary`；双方同时活动或互相派生均为Owner冲突。绑定不完整时两项继续按各自样本单位评分，不得用相似数值或统计相关代替语义等价。

## 条件组权重与结构化绑定

活动的`grouped_total_variation`、`grouped_wasserstein_1d`、`grouped_mean_absolute_error`及其他按条件组评价的合同，除`score_profile.group_weights`外还必须有`conditional_group_weight_binding`。支持以下两种确定性来源：

- `sealed_original_exposure`：保存原版事件集ID、相对证据路径、SHA-256、事件数、逐组暴露计数、token倍率和`normalize_positive_active_groups`。证据中的每个事件必须有唯一`event_id`和`conditional_group_id`，声明计数必须可逐事件重算。
- `source_metric_factors`：用别名精确绑定来源`metric_id + source_node_ids + instance_dimensions + target_evidence_sha256`；每个组由来源`target`或来源`group_weights`的明确键求和，再与正数常量相乘。来源实例不唯一、hash不一致、引用不活动字段或使用候选频率均阻塞。

退化条件组先移除，再对正权重活动组归一；目标组、权重组和绑定规则组必须完全相同。`persistent_state.position_role_dependence_residual_given_count_transition`还必须在`score_profile.residual_baselines_by_group`中逐活动组保存完整位置域基线。每组基线和为1，`baseline + target_residual`逐位置仍在0到1之间；角色数量为0或等于可用位置数时没有选择自由度，不得建立活动组。

非Owner指标必须保存与画像完全相同的结构化绑定。Value Symbol与倍率使用`owner_derivation_binding`和完整双射逐值复算；确定Cascade倍率使用`cascade_derivation_binding`，从`cascade.depth_distribution`与逐步状态映射复算倍率出现率、出现后应用率、生效倍率分布及层级依赖残差。确定映射下残差按`P(multiplier_state|step)-P(multiplier_state)`计算，不是恒为0；`group_weights`按原版中各实际结算步骤的暴露占比复算。

## 评分预算与多作用域

每个评分指标在目录中获得一个固定`score_budget_key`。同一预算键拆成多个组件、状态、盘面阶段或Feature实例时，先按密封的`scope_aggregation`聚合各实例得分，再使用一次指标权重进入评分组：

```text
作用域实例得分 → score_budget_key聚合 → 评分组加权 → 综合分
```

默认使用带密封`scope_weight`的`weighted_mean`；每个活动作用域实例必须显式提供有限正数`scope_weight`，运行时不得缺失后默认为1。需要防止局部严重偏差被平均掩盖时可在候选出现前密封为`minimum`。每个活动评分指标还必须显式密封有限正数`weight`；同一预算键的指标权重和聚合方法必须一致。禁止按实例数量直接累计权重。

全部活动评分组必须在任务合同顶层`group_weights`中逐组显式密封，键集合与活动评分组完全一致，每个权重为有限正数且合计为1。新任务必须使用`assets/policies/score_group_weight_policy.v1.json`和`apply_score_group_weight_policy.py`，按`normalize_active_base_weights`从语义域基础预算确定性生成；指标数量、作用域数量、候选频率和候选结果均不得改变组预算。不得为缺失评分组静默补1，也不得保留已全部退化或不适用的空评分组；任何人工覆盖都需要用户批准的新政策ID与hash。
