# 调参建议

## RSPR完整参数包

`Reel Set Profile Routing`（中文：`Reel Set 参数包路由模式`，简称`RSPR`）以`profiles_by_rtp`为识别标志。本节只适用于使用RSPR，且用户认证脚本能按该结构读取和模拟的游戏。其他架构只执行通用参数释放原则，不套用本节结构。

每个`ReelSet × rtp_group`是一套完整随机参数包。包内字段由Runtime与认证脚本动态确定，可包括选择权重、Reel、stop权重、高度权重、分层refill、特殊符号权重、Feature结果权重以及脚本支持的其他配置；不得把ReelSet只理解为Reel Strip，也不得把已知字段清单当成上限。

## 开放组合

在`parameter_authority`授权范围内，优化器可以自行：

- 新增、删除、克隆、拆分、合并或重新路由完整参数包；
- 调整参数包数量、名称、顺序、支持项和选择权重；
- 独立修改每套包内受支持字段的值、结构和配置项数量；
- 增减ReelSet、Reel内容与长度、stop支持、refill层和各类权重支持项；
- 为不同Mode、State配置不同数量和内容的参数包；
- 根据合同偏差和候选历史自行决定调参计划、参数组合与搜索方法。

基线中的A/B命名、参数包数量、字段顺序、Reel长度、refill层数、支持项和权重总和都只是当前状态，不是限制。Skill不规定先调什么、从几套开始、何时扩展或使用哪种算法。

## 多套ReelSet建议

对RSPR游戏，建议增加多套有明确差异的ReelSet完整参数包，用于承载不同的盘面、中奖、连锁或Feature场景需求。多套参数包通过Runtime声明的路由和选择权重共同形成最终体验，不要求每一套单独通过全部指标；优化器可以自行决定数量、分工、权重和包内参数，以整体候选通过冻结合同及最终FORMAL为目标。

场景选择必须在Runtime声明的选择作用域内按显式权重一次完成，不得根据已经生成的盘面、中奖结果、累计输赢或候选评分临时选择或切换ReelSet。

## 原子选择

按Runtime声明的选择作用域选择一次参数包，选择后该作用域内的初盘、stop、高度、refill和适用的Feature随机参数必须统一来自同一包。不得在运行中临时组合不同包的字段；需要组合时，先生成一套新的完整参数包，再让原生路由按显式权重选择。

## 边界

只使用认证脚本实际支持且已授权的Runtime配置。结构调整不得改变玩法语义、盘面几何、状态机、结算、随机步骤和RNG调用顺序；不得使用结果导向重抽、拒绝采样、回溯或失败换seed。
