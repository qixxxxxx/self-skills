## 实例输出

每个活动正式实例固定输出：

```text
实例ID
目标来源
冻结目标
候选结果
距离方法
实际距离
C级通过值及来源
偏差倍数
单项分
FORMAL等级
状态

```

观察项不伪造候选结果，固定保存在`metric_contract.coverage.observational_instances`，至少记录实例ID、目标来源、现有目标、原版样本证据、观察决定和原因。报告必须单独展示。

## 字段职责与唯一判定链

| 项 | 只负责什么 | 不负责什么 |
|---|---|---|
| 冻结目标`target` | 表示原版或用户确认的对齐参照 | 不单独决定通过，也不随候选变化 |
| 目标证据`target_evidence` | 说明目标样本是否达到最低线和建议线 | 不修改距离公式或放宽C级通过值 |
| 实例角色 | 在候选前把画像命中实例冻结为活动或观察 | 不能在看到候选结果后改角色 |
| 距离算法`distance.method` | 把目标与候选换算成同一种距离`D` | 不设置允许范围，不给等级 |
| C级通过值`c_budget` | 规定该实例允许的最大距离`T` | 不描述候选实际偏了多少，不参与二次放大 |
| 通过/不通过状态`status` | 在样本和数据可判定时，严格按`D <= T`给出通过或不通过 | 不读取偏差倍数、分数、卡分或分类分反向改判 |
| 偏差倍数`deviation_ratio` | 将不同单位的距离归一化，便于比较、评分、候选排序和报告 | 不设置独立门槛，不单独决定通过 |
| 单项分`score` | 表示接近程度，并在全部活动项通过后参与汇总 | 不能补偿失败实例，也不能把不通过改成通过 |
| 等级`formal_grade` | 通过项按分数细分S/A/B/C；失败、未知和不适用分别为F/U/NA | 不替代状态和样本充分性检查 |

统计实例固定按以下顺序处理：

```text
1. 校验样本、数据和合同状态
2. D = 距离算法(冻结目标, 候选结果)
3. 通过 = D <= T，其中T是候选出现前冻结的C级通过值
4. T > 0时计算R = D / T，供比较、评分、排序和报告使用
5. 先保留第3步的通过结论，再生成单项等级、卡分和分类分
```

观察项只执行证据分类和披露，不进入第2～5步。

确定性精确规则使用`T=0`：

- `D=0`：通过，偏差倍数为`0`，单项分为`100`，等级为S；
- `D>0`：不通过，偏差倍数为`null`，单项分为`0`，等级为F。

## 先判定再评分

所有N/J/P/B活动正式实例先执行唯一通过规则：

```text
通过 = 实际距离 <= C级通过值
```

任一活动实例失败，整体直接为F；其他高分不能补偿。`偏差倍数 <= 1`只是`T>0`时由`D <= T`推导出的数学结果，不是第二条通过规则，也不作为独立配置项保存。

`T>0`的统计实例再计算：

```text
偏差倍数 = 实际距离 / C级通过值
单项分 = max(0, 100 × (1 - 偏差倍数))
```

下表是对已完成判定结果的等级展示，不是另一套通过门槛：

| 偏差倍数 | 单项等级 | 含义 |
|---:|---|---|
| `<= 0.1` | S | 与目标非常接近 |
| `<= 0.2` | A | 差异稳定且较小 |
| `<= 0.3` | B | 有差异，但仍较接近 |
| `<= 1.0` | C | 已通过，但距离接近允许上限 |
| `> 1.0` | F | 由`距离 > C级通过值`得到的不通过结果 |

### 卡与分类怎么合并

- N卡：卡内活动实例等权；活动N1～N6卡等权得到N类分。
- J/P/B卡：先按合同中的`实例组 → 维度 → 卡`分层合并，避免档位或符号多的游戏天然占更大权重。
- 分布型实例组：完整时整体移动量占50%、各档平均占50%；整体移动量因缺桶转观察时，活动档位等权计分。
- mean/P50/P90三值组：三项等权。
- 每张活动卡必须全部通过后才产生卡分；分类内全部活动卡必须通过后才产生分类分。
- 当前N/J/P/B四个分类分都可计算，但跨分类权重未授权。最终等级只使用`score_scope=["N"]`，不得称为完整综合分。

全部活动实例通过后，当前阶段等级按N类分计算：S`>=90`、A`>=80`、B`>=70`、C`>=0`。

## 原版目标证据

机器事实源：`assets/policies/target_evidence_policy.json`。本节只管原版目标侧；候选、CALIBRATION、独立复核和FORMAL仍执行原样本政策，不跟随放宽。

### 判定时点与四种结果

每个画像命中实例都要在候选出现前记录原版有效分母。N3还要记录实际触发数；分布项还要记录该正式档位的原始计数。随后固定分类：

```text
有效分母为0                         → observe_no_evidence
任一必需计数低于最低可用线         → observe_low_sample
达到最低线但任一计数低于建议线     → active_low_sample
全部计数达到建议线                 → active_normal
```

`observe_*`进入观察清单，不要求候选测量；`active_low_sample`和`active_normal`都属于活动正式指标，使用完全相同的算法、通过值和FORMAL要求。低样本活动指标只是证据提示，不享受更宽容差。

### 建议阈值

| 指标 | 最低可用线 | 建议线 | 补充要求 |
|---|---:|---:|---|
| N1 | 不设样本线 | 不设样本线 | 只接受用户确认的唯一RTP |
| N2 | 200个完整入口 | 5000个 | — |
| N3 | 200个完整入口 | 5000个 | 同时至少5次触发；建议至少30次 |
| N4 | 200个完整入口 | 5000个 | — |
| N5 | 200个对应入口 | 2000个 | 每个Sigma作用域分别判断 |
| N6 | 500个完整入口 | 5000个 | 每个组件目标使用同一入口证据口径 |
| J1/J2/J3 | 50个对应结算或入口样本 | 200个 | 按各Facet冻结的真实分母判断 |
| P1 | 30个Feature入口或完整周期 | 100个 | P90改用最低100、建议200 |
| P2：`feature_entry`、`complete_feature` | 30次机会 | 100次 | — |
| P2：其他机会单位 | 50次机会 | 200次 | 包括spin、结算步、Pick、Respin和可见动作 |
| B1/B2 | 100张对应稳定盘面 | 300张 | 每个正式盘面作用域分别判断 |
| J2的P90 | 100个对应样本 | 200个 | 主要结构P90和单步奖励P90 |

分布的每个正式档位还必须至少观测5次，建议30次。任一档位低于5次时，先在候选前按玩家含义合法合并；无法合并时，该档位按自身证据转观察，整体移动量转为`observe_distribution_group`，其他计数达标档位仍为活动指标。不得删除低计数档位后重新归一化其余桶，也不能在候选结果出来后重新分桶。

### 覆盖范围

- 全部画像命中实例都是活动指标：`coverage.status=完整`。
- 存在一个或多个观察项：`coverage.status=有限`。
- 观察不等于不适用，不会自动造成U；它表示这部分原版目标不足以承担正式通过判定。
- 活动指标全部通过且覆盖完整：`完整范围通过`。
- 活动指标全部通过但覆盖有限：`有限范围通过`。

## 距离算法

### 绝对概率差

用于单个概率、比例和RTP：

```text
D = abs(candidate - target)
```

例子：目标20%，候选22.5%，距离为2.5个百分点，即`0.025`。不要写成“相差12.5%”后直接拿去和绝对C级通过值比较。

### 相对误差

只用于N5 Sigma：

```text
D = abs(candidate - target) / max(abs(target), 1e-12)
```

例子：目标Sigma为10，候选为11，距离为10%，即`0.10`。

### 绝对数值差

用于自然单位的mean、P50和P90：

```text
D = abs(candidate - target)
```

例子：原版P90玩法长度为18次动作，候选为21次，距离为3次动作。

### 总变差

用于互斥且完整覆盖的档位或结果状态：

```text
TV = 0.5 × sum(abs(candidate_i - target_i))
```

双方使用合同冻结的相同支持，并分别归一化为1。

例子：原版`[70%,30%]`，候选`[55%,45%]`，总变差为15个百分点。它可以理解为至少要移动15%的概率质量才能把候选变成原版。

### 半L1

只用于B1普通符号组占全部有效格的整体构成：

```text
half_L1 = 0.5 × sum(abs(candidate_i - target_i))
```

与总变差的公式相同，但普通符号组不重新归一化，因为关键符号单独统计，普通组占比之和可能小于1。

例子：原版普通组占比`高值40%、低值50%`，候选`高值35%、低值45%`，半L1为5个百分点。不能把两边普通组重新归一化成100%，否则会掩盖关键符号占比变化。

## N类C级通过值

机器事实源：`assets/policies/hard_gate_budget_policy.json`。

| 卡 | 距离 | C级通过值 |
|---|---|---|
| N1 | 绝对概率差 | `0.003` |
| N2 | 绝对概率差 | `min(max(target × 6%, 0.008), 0.02)` |
| N3 | 绝对概率差 | `target × 12%`；`target < 0.0005`时为`target × 20%` |
| N4 | 绝对概率差 | `min(max(target × 8%, 0.005), 0.015)` |
| N5 | 相对误差 | overall和非Feature为`0.08`；各Feature为`0.12` |
| N6 | 绝对概率差 | `min(max(target × 8%, 0.003), 0.015)` |

N1目标只接受用户确认的唯一标量。用户输入96%时，机器合同保存`0.96`。字典、数组、上下界或区间都无效，不得取中点。

N4固定为`P(return >= actual_entry_cost)`，边界包含1x；Feature Buy使用实际购买成本。

## J类C级通过值

机器事实源：`alignment_evaluation_policy.json.j_player_budget_rules`。

### J1 中奖组参与率

每个中奖组使用绝对概率差。

```text
Base：min(max(target × 10%, min(target, 0.008)), 0.025)
Feature：min(max(target × 12%, min(target, 0.008)), 0.030)
```

`min(target, 0.008)`保护稀有组。例如目标为0.17%，C级通过值为0.17个百分点，不会被直接放宽到0.8个百分点。

## 样本与档位冻结

### 原版目标侧

原版目标侧统一使用[原版目标证据](#原版目标证据)的“最低可用线 + 建议线”。样本数、N3事件数和分布档位计数必须进入`source_summary.json.targets`，由合同编译器在候选前确定性分类。低于最低线时保留观察项并继续流程；缺少计数字段、目标来源或画像适用性证据时才属于合同缺口。

### 候选与FORMAL侧

- 测量文件必须使用`slot-alignment.metric-measurements.v7`，绑定`task_id`、执行阶段和当前`metric_contract_sha256`；串任务、串阶段或多出合同外实例时在计算前拒绝。
- 每个活动测量都要回传`target_count`、`candidate_count`以及适用的候选最低要求。`target_count`用于核对冻结证据，不在评价阶段重新决定活动或观察角色。
- CALIBRATION样本不足可以继续晋级计算，但该实例保留U，不能当作通过。
- FORMAL按活动条件实例的整体分母选择样本档位，目标为每个条件实例至少`2000`个有效样本。
- `50000000`局仍不足时照常完成，受影响实例标为`样本不足/U`。
- 不得按某个稀有桶的次数单独提高FORMAL局数。

### 档位合并

- 只允许候选出现前合并。
- 有序数量向相邻高值尾部合并，例如`3`和`4+`合成`3+`。
- 无序状态只合并玩家难以区分、业务含义接近的状态。
- 合并后仍须互斥、完整覆盖并保留玩家含义。
- 候选出现后不得因为某一桶难通过而重新分桶。
- 原版档位合并后仍有档位低于5次时，该档位和整体移动量转观察；其余活动档位继续评价，候选或FORMAL侧不得删桶后重新归一化。

## 状态和失败去向

活动实例结果状态只允许：`通过`、`不通过`、`样本不足`、`计算异常`。卡还可以是`不适用`或`观察`；观察明细保存在合同覆盖清单，不伪装成活动实例结果。等级只允许：`S`、`A`、`B`、`C`、`F`、`U`、`NA`。

| 情况 | 实例状态/等级 | 是否继续 | 最终影响 |
|---|---|---|---|
| 距离不大于C级通过值 | 通过/S～C | 继续 | 可进入合并评分 |
| 距离大于C级通过值 | 不通过/F | 继续调参或交付失败结果 | 无未判定项时整体不通过 |
| 候选样本不足 | 样本不足/U | 继续其他计算 | 整体无法完整判定 |
| 算法、数据或数值异常 | 计算异常/U | 修复后重算；其他项可继续 | 整体无法完整判定 |
| 玩法确实不存在 | 不适用/NA | 继续 | 不参与通过和评分 |
| 原版目标低于最低证据线 | 观察/NA | 继续候选和FORMAL | 不参与通过和评分，覆盖范围变为有限 |
| 原版目标达到最低线但低于建议线 | 活动指标，按正常规则判定 | 继续 | 不放宽通过值，报告低样本提示 |
| 原版存在、候选结构不可达 | 不通过/F | 继续其他候选 | 不得删除实例 |
| 固定规则完全一致 | 规则审计通过/S | 继续 | 不生成统计分布实例 |
| 固定规则不一致 | 实现/合同错误 | 修复后重算 | 不能用普通审计忽略 |

最终状态优先级固定为：

1. 任一活动实例为候选样本不足、计算异常或存在未解决合同缺口：`无法完整判定/U`；
2. 无未判定项，但任一活动实例不满足`距离 <= C级通过值`：`不通过/F`；
3. 全部活动实例满足`距离 <= C级通过值`：活动判定状态为`通过`，再按当前N类分给出S/A/B/C阶段等级；
4. 第3步覆盖完整时结论为`完整范围通过`，覆盖有限时结论为`有限范围通过`。

## 完整算例

### 单实例

假设N2目标为20%，候选为21%，C级通过值为：

```text
min(max(0.20 × 6%, 0.008), 0.02) = 0.012
```

则：

```text
实际距离 = abs(0.21 - 0.20) = 0.01
偏差倍数 = 0.01 / 0.012 = 0.833333...
单项分 = 100 × (1 - 0.833333...) = 16.6667
```

该实例满足`距离 <= C级通过值`，但单项等级只是C。不能因为“通过”而描述成基本一致。

### 分布实例组

假设P1入场档位有3档，各档分分别为80、60、100，整体总变差分为70：

```text
档位平均分 = (80 + 60 + 100) / 3 = 80
实例组分 = 70 × 50% + 80 × 50% = 75
```

前提是参与正式评价的活动子项全部通过。若其中一个活动档位为F，即使算术平均仍高于70，也不产生可用于通过的组分；原版低于最低计数的档位及其整体移动量转观察，其余活动档位继续计算。

## 冻结与失效

以下内容必须在候选出现前冻结并绑定SHA-256：

```text
玩法画像
适用实例清单与顺序
目标及来源
原版目标证据计数、活动/观察决定和覆盖范围
作用域、分母和支持
距离方法
C级通过值
档位合并
样本执行计划
指标库与政策
Runtime、脚本和参数权限
Runtime与认证脚本能力确认
```

任一项变化都使已有基线、候选和FORMAL失效。修正拼写但改变了稳定ID，同样视为合同变化。不得对已冻结合同原地放宽、删项、改变分母，或根据候选表现改成观察项。
