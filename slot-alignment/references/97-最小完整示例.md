# 最小完整例子

某游戏画像识别到`feature.free-spin`，阶段 2 自动匹配 Core 与免费旋转指标。目标总 RTP 为 96%，FORMAL 得到 95.9%；目标中奖率 30%，候选 30.4%；免费旋转自然触发率目标 1.00%，候选 0.97%。三项都落在各自硬合同容差内，状态为`通过`。

新任务先应用默认硬指标容差系数。例如原版样本给出的中奖率基础绝对容差为0.3%，默认系数2.0，生效容差为0.6%；倍率分布基础TV容差为0.01，默认系数4.0，生效门槛为0.04。权威总RTP系数固定1.0，不扩大目标区间。

若原版 Base/Feature 派奖贡献占比分别为 25%/75%，权威总 RTP 区间为`[0.95, 0.96]`，则组件目标为 Base `[0.2375, 0.2400]`、Feature `[0.7125, 0.7200]`。不得把原版样本测得的 Base/Feature 绝对 RTP 直接作为目标。

预算允许按密封阶梯自动增加；但若独立、联合和边界扫描已经密封证明授权空间结构不可达，则立即停止扩张。只有扩权、目标/合同获批变化或实现错误修复使原证据失效后才能重新进入搜索。

当前Runtime基线评分若为`不通过`，阶段3仍需先生成固定scorecard和中文报告；随后运行阶段转换校验。只要评分可判定、指标完整且上游hash有效，`stage3_gate.json`仍可通过并允许进入阶段4调参。缺报告、报告被改写或只有`work/`临时scorecard时，门禁必须阻塞。

三个非硬指标得分为 90、82、76，原权重为 50%、30%、20%。综合分：

```text
90×0.50 + 82×0.30 + 76×0.20 = 84.8
```

虽然第三项低于单项 85，但综合分达到 80 且硬指标全过，所以最终可`通过`。如果第三项经用户批准豁免，则它退出评分，剩余权重重归一化：

```text
(90×0.50 + 82×0.30) / (0.50+0.30) = 87.0
```

最终只能显示`豁免后通过`。若总 RTP 超出红线，即使综合分 99，也仍是`不通过`。
