# 阶段 3B：硬指标容差系数

## 默认政策

新建任务必须在查看任何候选结果前加载并密封：

`assets/policies/hard_gate_tolerance_policy.v2.json`

v1只用于仍使用旧指标ID的历史合同，不再作为新任务默认政策。

默认系数：

| 硬指标 | 系数 |
|---|---:|
| 权威总 RTP | 1.0，锁定 |
| 完整付费入口中奖率 | 2.0 |
| Feature 自然触发率 | 1.5 |
| 200x 以下付费入口回报分布有序距离 | 4.0 |
| 总体及各适用作用域 Sigma | 1.5 |
| Base、Feature、其他组件 RTP 贡献 | 1.5 |
| 未列出的未来硬指标 | 1.0 |

## 计算规则

每个硬指标先从权威任务目标或原版样本资格得到`base_tolerance`，再计算：

```text
effective_tolerance = base_tolerance × tolerance_factor
```

`hard_gate_profile`必须同时保存：

```json
{
  "method": "wasserstein_1d",
  "bin_positions_source": "task_contract",
  "axis_semantics": "nonnegative_multiplicative",
  "position_transform": "log10_1p",
  "distance_normalization": "fixed_transform_unit",
  "distance_scale": 1,
  "distance_unit": "log10_decade",
  "base_tolerance": 0.01,
  "tolerance_factor": 4.0,
  "tolerance": 0.04,
  "tolerance_policy_id": "future-default-hard-gate-tolerance-factors-v2"
}
```

`tolerance`是生效容差，为兼容评分器保留。机器必须验证它等于基础容差乘系数，不允许手填不一致值。

## 区间指标

对`range_error`保持目标区间不变，容差只允许作为区间外扩展距离：

```text
通过条件：distance(candidate, target_range) <= effective_tolerance
```

权威总 RTP 的基础容差固定为 0 且系数锁定为 1.0，不得借系数扩大外部权威区间。组件 RTP 可使用任务密封的统计基础容差乘对应系数，但不得改变贡献占比目标本身。

## 版本与失效

- 本政策只适用于采用后新建的任务；已有合同、候选、报告和 FORMAL 不回溯修改。
- 新任务必须把政策 ID、版本、源文件 SHA-256、全部系数和锁定项复制到`metric_contract.json`。
- 系数必须在候选结果出现前密封；看到结果后修改系数，最小退回阶段 3，并使既有评分、冻结候选和 FORMAL 失效。
- 报告必须并列展示基础容差、系数、生效容差和硬门禁状态。
- 系数只放宽统计容差，不得改变目标、玩法、RNG、封顶、结算语义或样本资格。
