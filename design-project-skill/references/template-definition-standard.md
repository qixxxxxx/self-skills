## 一、先判定治理等级

讨论文件结构、报告模板或生成脚本前，先选择能够覆盖真实风险的最低等级。等级由流程依赖、错误代价和可复算要求决定，不按文档长度、文件数量或“看起来专业”决定。

| 等级 | 典型特征 | 默认治理强度 |
|---|---|---|
| 简单 Skill | 单一职责；通常只有一步或两个无门禁步骤；输出短且可直接人工核对；无评分、审批链、目录型知识库和版本封存 | 轻量输出约定，不强制机器事实源、Hash、生成器或独立汇总文档 |
| 标准 Skill | 具有2～4个稳定步骤；重复生成一份或少量固定输出；存在结构化字段、脚本或常见异常，但不需要复杂阶段封存 | 完整模板契约；按错误风险选择确定性脚本和轻量校验 |
| 复杂多阶段 Skill | 存在依赖阶段与阶段门禁、评分/权重/阈值、CALIBRATION或FORMAL、机器与人类双产物、版本/Hash/封存/恢复、目录型知识库、多角色交接、高风险外部副作用之一 | 机器事实源、确定性报告、跨阶段身份、证据链和重渲染校验按需完整应用 |

以下任一条件成立时，不得继续按简单等级设计：

- 前一阶段产物是后一阶段正式输入，且跳过或错序会改变结论。
- 人类报告会用于审批、上线、合规、数值验收或其他高代价决定。
- 存在综合评分、硬门禁、样本要求、调参、候选筛选或独立正式验收。
- 机器结果与人类报告必须长期保持确定性等价。
- 需要不可变版本、Hash绑定、恢复、历史复算或交付后独立审计。
- 存在大量可复用指标、规则、动作或玩法条目，需要Owner、去重和目录维护。
- 会调用生产、发布、数据库写入或其他不可逆/高风险外部能力。

信息不足时先标记“暂定等级”，只询问一个会实际改变结构、成本或风险的关键问题。不得因为本设计 Skill 自身使用事务状态，就默认把所有目标 Skill 设计成复杂等级。

## 二、所有等级的共同底线

- 输出必须服务于明确用户和判断目的，不能只追求格式完整。
- 固定字段需要说明含义；同一概念保持同一名称和单位。
- 必须区分“无数据”“不适用”“无法判定”“失败”和“通过”，不得静默留空或把缺失误报为成功。
- 至少提供一个与真实使用场景一致的短例子。
- 结论必须能追溯到输入、规则或证据；追溯强度随等级提高。
- 只有字段选择会改变范围、评价、责任或成本时才增加用户确认；普通排版细节由AI按已确认目标补齐。

## 三、简单 Skill

### 适用方式

- 输出规则可以直接写在`SKILL.md`，或放入一个短reference；不要为了形式创建多份空模板。
- 没有固定结构时，只约定“必须回答什么”和成功条件，不强制章节、表头或编号。
- 有短固定输出时，只需定义：输出目的、必需内容或字段顺序、无数据怎么办、一个完整实例。
- 内容可以由AI直接生成；只有重复计算、格式易错或需要稳定复用时才增加脚本。

### 默认不要求

- 独立机器JSON事实源。
- 报告Hash、版本目录和不可变封存。
- `render_*`与重渲染一致性验证。
- 独立的`index.md`、生成式汇总文档或Owner矩阵。
- 为每个小节分别写七项展示契约。

### 简单参考

```markdown
输出固定包含：结论、主要依据、一个风险或限制、下一步。
资料不足时结论写“无法判断”，并指出最小缺失资料。
```

## 四、标准 Skill

存在固定报告、清单、审批单、阶段总结或重复交付文档时，每个稳定章节定义：

1. **展示目的**：本章回答什么问题，供谁判断。
2. **展示方式**：表格、列表、单段结论、代码块或图示。
3. **必需字段与顺序**：固定字段名、单位、含义和排列顺序。
4. **数据来源**：来自用户输入、阶段产物、脚本结果或证据。
5. **空值规则**：无数据、不适用、无法判定和失败怎样展示。
6. **展示实例**：一段字段和顺序一致的短Markdown实例。
7. **一致性检查**：需要校验的章节、字段、表头、占位符和数据关系。

同类章节保持字段名、单位、顺序和空值表达一致。需要复制使用的真实模板放入`assets/`；定义性规则放入`references/`。重复执行或人工容易出错时增加确定性生成或校验脚本，但不因“可能以后有用”预先搭建完整封存体系。

```markdown
## 阶段验收结果

- 展示目的：让用户判断是否进入下一步。
- 展示方式：四列表格。
- 必需字段与顺序：检查项、当前结果、通过标准、结论。
- 数据来源：本阶段验证结果。
- 空值规则：缺少结果写“无法判定”；不适用时说明理由。
- 一致性检查：检查表头、必需字段和结论来源。
- 展示实例：

| 检查项 | 当前结果 | 通过标准 | 结论 |
|---|---|---|---|
| 结构校验 | 通过 | 无错误 | 通过 |
```

## 五、复杂多阶段 Skill

复杂等级除完整章节契约外，根据实际命中条件应用以下增强规范；未命中的项目明确记为“不适用”及理由，不机械创建空基础设施。

### 5.1 机器事实与人类阅读分层

- 计算状态、评分、门禁、审批和正式结论以机器可读产物为事实源。
- 中文Markdown是人类阅读视图，由确定性生成器产生，不得手工改写来改变机器结论。
- 百分比、业务单位和中文标签等阅读转换必须能映射回机器值。
- 验证器重渲染并比较章节顺序、字段、表头、状态和结论；发现漂移时阻塞阶段转换或交付。

### 5.2 阶段报告合同

- 每阶段先生成固定机器产物，再生成对应人类报告并通过转换门禁。
- 阶段模板保存在`assets/templates/`，生成器和校验器放在`scripts/`，详细字段规范放在`references/`。
- 阶段之间沿用稳定对象ID、分类、编号、顺序、标题和单位，使“目标→基线→正式结果”能够直接纵向比较。
- 主表只放标量摘要和结论；数组、对象、指标清单、审批和错误拆成明细表，禁止直接倾倒JSON。
- 长路径在摘要中使用稳定证据ID，在同章路径/Hash表中展开。

### 5.3 证据、版本和政策

- 关键输入、合同、生成器、政策和正式产物按风险需要绑定版本与Hash。
- 权重、容差、阈值、样本计划、评分方法和预算在候选结果出现前冻结；不得看结果后放宽。
- 报告保留复算命令、输入身份和失败证据；交付版本需要不可变时禁止覆盖历史。
- 交付后独立审计若不应改变正式结论，必须隔离在正式封包之外，只生成警告并明确“既有状态影响：无”。

### 5.4 状态与空值

- 固定章节不得因无数据而删除；使用“无、不适用、样本不足、无法判定、阻塞、已豁免”等受控状态。
- 阶段门禁、综合评分和审计结论分开表达；综合分不能掩盖硬门禁失败。
- 缺失、异常和样本不足不能默认按0分或通过处理。

### 5.5 语义Owner与防重复

- 同一语义变量只有一个主Owner；可由主结果确定性推出的摘要标记为派生诊断，不重复计分。
- 多作用域实例先按稳定预算键聚合，再进入顶层评分组，不能靠拆指标或拆作用域增加权重。
- 交叉门禁、审计项和互斥指标说明重叠理由及责任边界。

## 六、目录型知识与中文汇总

只有目标 Skill 维护大量可复用指标、规则、动作、玩法或其他目录条目时才应用本节。没有目录型知识的复杂 Skill 不需要为了形式创建汇总文件。

推荐职责：

```text
references/<目录>/index.json     包、分类、版本和文件Hash索引
references/<目录>/**/catalog.json 唯一机器事实源
references/<目录>/index.md       中文介绍、分类导航、包映射和责任边界
references/<目录>/汇总.md         从JSON确定性生成的全量中文阅读入口
scripts/generate_summary.py       确定性生成汇总
scripts/validate_catalog.py       缺项、重复、关系和过期校验
```

`index.md`负责解释分类、适用范围、包映射、Owner和“公共目录与单任务合同”的责任边界，不复制全部条目。

生成式汇总至少按实际需要包含：

- 目录版本、Schema、来源指纹和生成器身份。
- 分类数量与快速索引。
- 共用评价或处理方案，避免每项重复解释。
- 每个条目的中文说明、使用场景、目标含义、单位、适用条件、数据来源、评价方法和缺失策略。
- 派生、交叉核对、互斥Owner和防重复导航。
- 主动忽略范围和扩展条件。
- 维护及重新生成方法。

汇总禁止手工维护。目录条目、关系、单位或评价变化后必须重新生成；缺项、重复、过期、占位标签或具体机器绝对路径应使校验失败。

## 七、升级、降级与讨论落档

- 讨论阶段在`ACTIVE.md`记录等级、判定依据、命中的增强规范和明确不适用项。
- 用户确认后，把等级与输出治理合同写入相关阶段文件和`DECISIONS.md`。
- 项目新增阶段门禁、评分、目录、外部副作用或复算要求时，重新评估并升级；不能继续沿用过轻结构。
- 只有相关风险和要求确实移除后才能降级，并记录为什么删除重型组件仍不损害验收。
- 用户要求“保持简单”时优先删除无价值的分册、脚本、Hash和汇总层，但不能删除已经命中的安全、授权或可复算门禁。
- 恢复项目时从现行状态读取已确认等级，不依赖聊天重新判断。

## 八、分级验收

### 简单 Skill

- 输出包含约定内容、空值处理和真实例子。
- 没有为不存在的风险创建空模板、目录或脚本。

### 标准 Skill

- 稳定章节具备七项契约，字段、顺序、单位和实例一致。
- 重复或易错操作已有与风险相称的生成/校验方式。

### 复杂多阶段 Skill

- 阶段机器产物、人类报告和转换门禁一致。
- 稳定ID、版本、Hash、政策冻结、空值状态和复算链按命中范围完整。
- 有目录型知识时，JSON事实源、介绍索引、中文汇总和校验器一致。
- 没有重复Owner、重复评分预算、手工改结论或事后放宽标准。

任何等级都必须同时检查两类错误：简单 Skill 是否被过度建设，复杂 Skill 是否因追求简短而缺少必要治理。
