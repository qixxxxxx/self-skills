# 输出模板定义标准

## 适用时机

项目讨论涉及报告、清单、审批单、交付文档、阶段总结或其他固定结构的人类可读输出时，自动应用本标准。模板定义属于阶段契约的一部分，不等用户额外提醒。

如果字段选择会改变业务范围、评价口径、责任或成本，仍需在当前确认点中让用户确认；只补齐展示形式和空值规则时不另开确认点。

## 每个章节必须定义

1. **展示目的**：本章回答什么问题，供谁判断。
2. **展示方式**：表格、列表、单段结论、代码块或图示；优先选择最容易核对的形式。
3. **必需字段与顺序**：写出固定字段名、单位、含义和排列顺序，不只写章节名。
4. **数据来源**：字段来自哪个机器结果、阶段产物、用户输入或证据。
5. **空值规则**：无数据、不适用、样本不足、无法判定和失败分别如何展示；不得静默留空或伪造通过。
6. **展示实例**：提供一段短小但完整的 Markdown 实例，字段名和顺序与正式模板一致。
7. **一致性检查**：说明是否校验章节顺序、字段存在、表头顺序、占位符和机器结果一致性。

同类章节保持同一字段命名、单位、顺序和空值表达。字段变更必须同步更新模板、生成逻辑、校验规则和相关实例。

## 简短参考模板

```markdown
## 三、阶段验收结果

- 展示目的：让用户判断本阶段是否可以进入下一阶段。
- 展示方式：四列表格，一项门禁一行。
- 必需字段与顺序：检查项、当前结果、通过标准、结论。
- 数据来源：阶段机器结果和已密封证据。
- 空值规则：缺少结果时写“无法判定”；不适用时写“不适用”并说明理由；不得留空。
- 一致性检查：校验章节存在、表头名称及顺序、无占位符，并与机器结果一致。
- 展示实例：

| 检查项 | 当前结果 | 通过标准 | 结论 |
|---|---|---|---|
| 指标可测率 | 100% | 100% | 通过 |
| FORMAL有效性 | 无数据 | 必须有效 | 无法判定 |
```

## 讨论过程中的自动落地

- 讨论阶段输出时，在`ACTIVE.md`当前确认点中记录“输出模板契约”，包含上述七项。
- 用户确认阶段规则后，将模板契约一并写入对应`stages/`文件和`DECISIONS.md`；不得只保存章节目录。
- 恢复项目时，从现行阶段文件恢复模板字段和实例，不依赖聊天记录重新推测。
- 制作目标 Skill 时：定义规则放入`references/`；需要复制使用的真实模板放入`assets/`；需要稳定生成或验证时再增加`scripts/`。

## 最低验收

- 每个章节都能说明“展示什么、怎么展示、字段是什么、无数据怎么办”。
- 每个章节至少有一个可直接理解的Markdown实例。
- 同一模板内字段名称、单位和顺序一致。
- 无数据与不适用不会被误读为通过。
- 后续实现者无需根据章节名自行猜测内容。
